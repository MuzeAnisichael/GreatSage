# v0.2 开发验证记录

2026-09-27，`0.2.0-alpha.1`，分支 `feat/v0.2-quality-memory-audit`。以下区分机制交付、小型评测结果和未达标部分；六项机制实现不等同于所有质量目标都通过。

## 固定基线

`evals/decisions.json` 为项目编写的 20 个对话边界场景，不是真人会话样本。v0.1 规则准确率 0.65，7 个误触发、0 个漏触发。`evals/memory.json` 是 6 条虚构记录和 5 个改写查询，v0.1 词法检索 Recall@3 为 0.20。结果保存在 `evals/baseline-v0.1.json`；语料哈希按规范化 JSON 计算，避免 Windows 换行影响对比。

## 语义记忆与预算阶段

- 自动化：166 passed、4 skipped；`npm run check` 通过。
- 使用本机已配置凭据，真实 OpenRouter `openai/text-embedding-3-small`：5 个查询 Recall@3=1.0，P50=594 ms、P95=618.8 ms。六次嵌入请求（一次记录批次、五次查询）共 245 个输入 tokens，服务返回总成本约 0.0000049 美元。
- 本机 Ollama `bge-m3:latest`：5 个查询 Recall@3=1.0，P50=2328 ms、P95=2581.2 ms，部分重复文本查询命中服务缓存，不能将 16 ms 当作普通查询时延。首次使用 15 秒后台超时触发失败；后台请求上限调整为 60 秒后完成。前台检索有独立等待上限，默认 1.5 秒，因此慢查询将回退词法检索；上述召回率是未应用前台等待上限的嵌入能力测量。
- 真实下载并校验 `o200k_base` 编码文件成功；默认 Gemini 模型继续使用保守字节预算。明确支持的 GPT 编码只有手动准备后才启用，不将通用编码描述为所有模型的精确计数。
- 运行报告保存在忽略目录 `.runtime/eval/`。测试只使用虚构记录，不向服务提交用户历史。

向量删除/修正失效、维度变化、模型隔离、无效响应、后台过期提交和旧版配置兼容均有自动化覆盖。此阶段的新桌面控件仅完成语法检查，完整交互和打包验证在整合阶段执行。

## 记忆、审计与语音整合阶段

- 冲突候选隔离、替换/丢弃/共存、来源删除失效、旧会话压缩、分层回查和分页已实现。请求快照默认只有哈希和元数据，全文需先开启，正文上限 256 KB；来源删除会失效，日志保留期同样适用，重启标记未完成请求。
- 结构化旁听判断真实调用 OpenRouter `google/gemini-2.5-flash-lite`，20 个固定文本场景全部符合标签，无服务失败，P95=745.75 ms（包含规则快速路径）。早先仅约束提示词的试验有 2 次格式失败和 1 个漏答；加入结构化输出后复测上述结果。固定开发集成绩不代表陌生会话的泛化准确率。
- Google FLEURS CC BY 4.0 中文 validation 的 3 段真人朗读（18.38/7.44/7.56 秒），重复 3 轮共 9 次识别，字符错误率 5.079%，请求到识别完成 P50=1500 ms、P95=2106.2 ms，失败 0。原始文本及授权信息在 `evals/speech.json`、`evals/audio/ATTRIBUTION.md`。不是自发交谈样本。
- 同一组录音降为 15% 幅度，单轮 3 次 CER=4.762%，P50=1563 ms、P95=2364 ms；仅验证 ASR 接口，没有经过真实麦克风或 VAD。
- 使用真人录音进行数字模拟：0.4 倍参考声、180 ms 延迟、另一段 0.5 倍人声重叠。20/100 ms 音频批次中，纯回声的 382 个有效语音帧被抑制，重叠情况下 664 个独立人声帧没有被静音。100 ms 批次滤波 P95 约 0.7 ms。这不是房间回声实测或完整 AEC。
- 全套最终回归 187 passed、4 skipped，`npm run check` 通过。跳过项为显式启用的真实设备枚举/麦克风/SAPI 检查，以及当前 Windows 权限不足的符号链接创建测试；并非相关功能全部通过。功能里程碑 eaa9ca6 的 GitHub Windows CI 成功。
- 源码 Electron 桌面 23 项检查通过，覆盖设置保存、Skills、记忆增改删、冲突共存裁决、源文详情/分页、审计默认隐藏正文及显式查看、删除来源清除正文、日志、桌宠和子进程退出。测试数据隔离且未开启麦克风。执行环境的沙箱最初阻止进程通信，使用正常权限复测通过；没有关闭 Electron 自身的沙箱。
- PyInstaller 与 electron-builder 已构建 `release/win-unpacked/GreatSage.exe`（版本 0.2.0.0）。Electron 测试宿主加载包内 `app.asar`、包内页面和冻结 Python 后端，`--packaged --live --parallel-sources` 的 29 项检查全部通过，新增覆盖真实 API 流式回答、静音 Windows 系统语音播放/取消、并发音源枚举、元数据文件下载以及包内 o200k 编码下载/校验/加载。未开启麦克风。该目录包尚未发行签名（NotSigned），需保留整个目录，尚未在另一台电脑验证。

## 完整管线与长期摘要

- 完整 API 管线使用第 3 段 FLEURS 录音按 30 ms 注入真实 Runtime/VAD，模型为 Whisper large-v3-turbo → Gemini 2.5 Flash Lite → Qwen Audio 3.0 TTS Flash。最早一次分段 CER=42.3%，定位到 RMS 条件短路导致 WebRTC VAD 未接收低音量帧；改为每帧更新检测器后，3 轮均成功、平均 CER=3.846%。
- 修复后三轮从最后一帧 VAD 语音算起：到稳定转写 P50=2542.74 / P95=2742.378 ms；到首字 3144.51 / 3253.608 ms；到音频就绪 4899.73 / 5009.215 ms。停止静音判定约 578 ms。**未达到首字 1–2 秒和起播 2–3 秒的目标**，且音频就绪不等于真实播放；n=3 不能视为稳定 SLA。
- 三轮各取消了一次临时 ASR 请求，远端未回用量时记为未知。Python 进程峰值 RSS（250 ms 抽样）76.88 MiB；不含 Electron、Ollama、驱动或整机峰值。先前 Windows 系统语音在受限执行环境中因 COM 缓存权限失败，API TTS 的上述链路通过。
- 本机 Ollama qwen3:4b 的 20 个旁听场景在 3 秒上限内有 6 次语义失败、2 个漏答、无误触发，准确率 90%。该配置不能冒充低延迟本地替代；明确叫名的快速路径可用，也可关闭语义判断。服务可用性和实时可用性是不同结论。
- 32 个虚构会话共 64 条记录，真实 LLM 生成 37 个摘要并达到第 3 层。早期模板反复输出来源 ID、输出上限 512 tokens，最上层的项目/口令字面保留率为 34.375%；调整为来源关系单独存储、优先保留事实对应关系、最多 768 tokens 后，复测 100%，后台失败 0，重启保留与源删除失效通过。该指标只检测字面共现，不证明复杂事实关系全部正确；原文始终保留。

本轮测试只使用虚构记录及明确授权的公共录音，未提交用户历史。可公开指标汇总见 [results-v0.2.json](../evals/results-v0.2.json)，保留每次开发试验的原始版本标记；完整本机报告在 `.runtime/eval/`。命令和比较口径见 [evaluation.md](evaluation.md)。
