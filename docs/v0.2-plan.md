# GreatSage v0.2 开发方案

2026-09-27：用户确认完整覆盖 roadmap 中 v0.2 的六项，以本机 Windows、API 优先并支持 Ollama 为基准，分阶段提交。上一轮首配清单及界面重排方案搁置。

## 交付范围与验收

| 方向 | 本版交付 | 验收依据 |
| --- | --- | --- |
| 语音回应质量 | 旁听的语义决策与明确叫名快速路径、主动回应去重、音频缺口与回声处理改进 | 标注场景集的误触发/漏触发；真人录音回放及有标签的模拟回声/重叠输入；不冒称完整 AEC |
| 可重复评测 | 固定版本的回应、跨会话记忆、语音评测集；离线/真实服务运行及版本报告对比 | CER、召回率、决策准确率、延迟 P50/P95、失败/取消/用量；区分合成与真人、音频就绪与实际播放 |
| 检索与预算 | API/Ollama 嵌入、词法与向量混合检索、版本化索引、适用模型 tokenizer 与保守降级 | 改写查询可召回；不同模型索引不混用；服务失败回退；最终请求和输出预留满足预算 |
| 长期记忆 | 冲突候选及用户裁决、修正后失效、旧会话压缩与多层摘要、逐层来源查看 | 冲突不静默覆盖；删除/修正同步清理索引、摘要和派生回答；重启继续处理积压原文 |
| 可追溯审计 | 配置与实际 Skill/请求内容快照、按 trace 查看和受控导出 | 默认仅元数据；全文归档显式启用；无凭据；来源删除使相关正文快照失效；外部 Skill 改动不改变已保存快照 |
| 后台恢复 | 有限批次、前台优先、失败退避、重启续建、音源异常与 ASR 用量记录 | 故障不会高频重试；旧任务不能写回；后台状态可见；音源全失败不继续假报监听 |

## 默认行为与实现约定

- 新增向量检索独立配置，支持 OpenRouter/OpenAI 兼容 API 与 Ollama。默认关闭；用户启用后界面明确说明历史文本将用于建立索引，可暂停和重建。关闭或故障时仍可词法检索。
- 新旧配置及数据库兼容迁移，原文和显式记忆保留。向量按嵌入模型/地址/内容版本隔离；不对用户运行数据做开发测试。
- tokenizer 仅在对应编码可用时使用，记录编码与估算口径；未知模型使用保守字节上界。消息封装开销与输出预算单独预留，不能把通用编码称为所有模型的精确计数。
- 记忆冲突由候选提示和明确选择处理，保留双方来源；识别不确定时不自行裁决。摘要是参考，不提升媒体内容为用户事实。
- 审计全文快照默认关闭；开启后记录实际请求及注入的 Skill 文本。导出明确区分元数据与包含正文，沿用本地数据删除语义。
- 前台交互优先于嵌入/压缩；后台失败保留原文并退避重试。模型/数据代际变化后丢弃过期结果。
- v0.2 的界面改动服务于新增记忆、审计和任务状态入口。电脑操作及工具执行继续按 roadmap 在 v0.3 设计。

## 提交顺序

1. 评测口径、固定场景集与可比较报告。
2. 嵌入适配、混合检索和上下文预算。
3. 冲突处理、分层摘要与来源回查。
4. 快照、导出和后台调度；整合语音判断、回声/缺口及状态修复。
5. 自动化、真实 OpenRouter/Ollama、桌面交互与目录包验证；更新版本、文档及测量结果。

每阶段只记录实际通过的检查。真人房间回声、长期运行与跨机器兼容没有测量就保留为未验证项。
