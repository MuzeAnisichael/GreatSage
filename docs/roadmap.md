# GreatSage 版本与优化路线图

更新日期：2026-09-04。

状态：规划草案。版本号用于组织范围，当前仅完成需求讨论与文档初稿；未承诺完成日期。

## 1. 已确认的版本边界

- 首版包含完整的语音秘书基本闭环、三种回应模式、长期／跨会话记忆、上下文压缩、日志与桌宠。
- ASR、LLM 和 TTS 均支持本地与云端；考虑普通个人电脑配置，首版优先完善 API 体验。
- 后续引入打开软件、修改文件、执行命令、工具调用。
- 首版不加入定时提醒；内容触发提醒属于首版，定时提醒仅列为后续候选。
- 首版功能实现后再考虑其他运行环境兼容。
- 非语音声音理解和更多电脑信息输入属于后续扩展。

下面各版本的具体拆分和排序为建议。

## 2. v0.1：本机语音秘书

### M0：需求与架构确认

- 确认整体方案和默认设计，明确数据保存、语音服务支持范围、预设与桌宠交互。
- 汇总已确认范围、关键设计、假设和验收条件，取得用户对启动正式实现的确认。
- 基于已确定的 GreatSage 工程名，确认目录结构和技术栈。

### M1：工程、事件与音频基础

- 建立独立 Git 仓库、public GitHub 仓库和配置加载机制。
- 建立事件类型、关联标识、基础日志及动态日志视图。
- 实现麦克风与单一桌面音源采集、音源选择和来源标记。
- 验证切换设备／程序、音源无声和程序退出的行为。

### M2：实时语音交互

- 接入语音识别、轮次管理、Ollama、OpenRouter、文字输出和语音合成。
- 优先跑通 API 语音识别 → API 语言模型 → API 语音合成的完整链路，再完成本地与混合配置验证；全部属于首版范围。
- 实现流式输出、播放队列、打断和过时任务取消。
- 测量从说完到首段文本／首段语音的各阶段延迟。
- 分别记录 API 模式和本地模式的资源使用，验证 API 模式不依赖大型本地推理模型。
- 处理重复收音、助手自身声音回流和网络异常。

### M3：行为与记忆

- 实现全局 Prompt、预设与首版 Skills。
- 实现现成 `SKILL.md` 技能目录的导入、启停、按需加载与版本追踪；展示尚未支持的工具依赖。
- 实现对话、旁听问答、主动解释／提醒及优先级调度。
- 实现近期原文、历史检索、偏好／显式记忆及跨会话恢复。
- 实现上下文预算、压缩、摘要版本和来源回查。
- 实现记忆查看、修正、删除和派生数据更新。

### M4：桌宠与产品界面

- 实现 Q 版桌宠、摸摸、对话气泡和基础状态动画。
- 提供设置、聊天历史、记忆和日志入口。
- 完成输出语言／声音配置和状态可见性。

### M5：首版验收与发布

- 按 requirements.md 完成针对性验证，报告延迟和语音理解结果。
- 验证长时间监听、跨会话恢复、压缩与删除一致性。
- 更新安装、配置、使用说明、已知问题与测试结果。
- 完成阶段版本标签及 GitHub 发布记录。

M1–M4 均为首版内部里程碑，不应将某个中间演示视为已交付全部首版需求。

## 3. v0.2：质量与性能优化（建议）

- 根据本机实测结果优化语音识别、轮次结束判断、首段响应和打断延迟。
- 优化同时监听时的来源区分、回声处理与主动回应时机。
- 改善噪声、中英混合、术语、人名和数字的识别与历史检索。
- 优化长期运行的 CPU、显存、内存、磁盘和云端调用开销。
- 引入可重复的语音／记忆评估样例和版本间结果对比。
- 完善记忆冲突处理、摘要质量和审计回查体验。

性能与正确性问题若阻碍首版核心功能，应在 v0.1 内解决，不能以“以后优化”替代首版验收。

## 4. v0.3：工具与电脑操作（建议）

- 增加统一工具注册、参数校验、调用结果和审计记录。
- 支持打开软件、限定范围内的文件操作和命令执行。
- 评估 MCP 等工具接入方式。
- 明确用户指令、观察到的媒体内容和工具返回内容的来源与权限关系。
- 为有副作用的操作设计可查看的执行计划、授权范围、失败处理和可行的撤销方式。
- 使长任务执行与实时对话协调，保持可打断及进度可见。

具体执行权限和批准方式在该版本需求阶段确认，不由首版监听权限自动推导。

## 5. v0.4 及以后：信息输入与平台扩展（建议）

- 扩展屏幕、窗口文字、截图等电脑信息输入。
- 评估非语音声音事件理解，以及多个指定程序同时监听。
- 根据实际需要适配其他 Windows 版本、macOS 和 Linux。
- 扩展桌宠素材、动作和形象渲染能力。
- 评估更多本地／云端模型和更完善的技能分发、升级机制。
- 根据后续需求评估定时提醒、持久化日程与到期通知，首版不实现。

## 6. 持续维护方式

每个阶段结束时更新：

1. 已交付功能及其验证证据。
2. 仍未解决的问题、影响范围和下一步。
3. 各阶段延迟、识别／记忆质量和资源使用结果。
4. 当前代码与原设计的差异及原因。
5. 下一版本的明确范围和依赖。

优先级建议：输入和记忆正确性 → 核心交互可靠性 → 延迟与资源使用 → 桌宠表现扩展。
