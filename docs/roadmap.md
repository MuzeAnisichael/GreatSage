# GreatSage 版本与优化路线图

更新日期：2026-09-04。当前为 **v0.1 alpha 实现与验证阶段**；版本号组织开发范围，不承诺完成日期。

## 1. 已确认的边界

首版包含人的语音理解、三种回应预设、API／本地服务、长期与跨会话记忆、上下文压缩、日志和桌宠。API 体验优先，同时保留本地与混合配置。

首版不含定时提醒、电脑操作、命令与工具执行。打开软件、修改文件和工具调用是明确的后续目标；非语音声音、多种电脑信息输入及其他平台放在首版之后。

## 2. v0.1 alpha：已经落地的实现

| 方向 | 当前机制 | 仍须验证的部分 |
| --- | --- | --- |
| 工程与桌面 | 独立仓库、Electron 主窗口／桌宠／托盘、本地 Python 服务 | 安装体验、长期进程稳定性与打包分发 |
| 音频 | 麦克风与系统／指定进程、VAD、分段快照 ASR | 真实设备、程序退出／切换、噪声和重叠发言 |
| 响应 | 全局指令、三预设、流式文字、分句语音、取消 | 语义判断、主动插话时机、真实端到端延迟 |
| 模型 | 本地／云端适配、混用、独立配置与错误反馈 | 具体服务／模型组合的音频能力及资源开销 |
| 记忆 | 显式记忆、跨会话、词法检索、后台摘要、来源和级联删除 | 关键事实保持率、长周期规模和冲突体验 |
| Skills | 只读导入、启停、相关性选择、版本及受限文本引用 | 复杂技能目录兼容性与实际任务效果 |
| 审计 | trace、来源、配置／技能版本、阶段指标、动态日志 | 真实播放测量、跨版本复现和受控导出 |

自动化回归针对过期任务、预算、身份、删除和凭据等具体风险提供证据；它不能替代真实语音识别、自然对话和长时间运行测试。

## 3. v0.1 稳定化优先级

### P0：首版核心链路与数据正确性

- 验证真实麦克风、系统整体、指定程序与同时监听，报告不支持的场景。
- 验证 API、本地及混合语音链路；将可用模型、错误和必要准备步骤写入配置说明。
- 修复来源混淆、旧识别／旧回答复活、播放中断、重连缺段和数据删除问题。
- 完成主界面、独立桌宠、托盘、启动关闭和必要故障路径验证。

### P1：实时性、识别准确率与运行成本

- 对已确认的文字、语音和打断目标完成端到端实测；未达标时公开原因与下一步。
- 评估原生流式 ASR，减少重复快照识别的延迟和云端调用开销。
- 改善轮次结束判断、麦克风回流和用户打断；逐步评估完整 AEC，而不是把现有抑制措施称为 AEC。
- 用人名、数字、术语、中英混合和会议样本评估识别与历史回答。
- 记录持续监听的 CPU、内存、显存、磁盘与 API 成本。

### P2：可用性与发布

- 完善历史分页、源文定位、摘要查看、录音回放与解释性错误。
- 整理验证记录、使用说明、已知问题、版本标签和发布记录。
- 完成独立后端打包、桌面分发与全新环境安装验证。
- 精简 API 模式所需依赖，避免要求普通电脑安装大型本地模型。

阻碍首版核心功能的错误在 v0.1 内处理，不能以“后续优化”替代验收。发布 alpha 是让实现可检查和试用，不是把所有目标标记为完成。

## 4. v0.2：质量、记忆与审计增强

- 用真实语料改进旁听提问识别、主动插话与回声处理。
- 提供可重复的语音、延迟和长期记忆评估集及版本间对比。
- 接入适用的 tokenizer 和语义检索，改进不同措辞下的历史召回。
- 完善记忆冲突、用户纠正、长周期分层摘要和来源回查。
- 设计受控配置／Skill 快照与导出，使审计更接近可复现。
- 优化后台任务优先级、失败恢复和资源使用。

## 5. v0.3：工具与电脑操作

- 统一工具注册、参数校验、结果、错误与审计格式。
- 支持打开软件、限定范围的文件操作和命令执行。
- 评估 MCP 等工具接入方式，以及现成 Skills 的外部依赖。
- 区分用户指令、媒体观察和工具输出，明确可执行操作的授权来源。
- 对有副作用的操作提供可查看的范围与执行记录，并设计失败处理和可行撤销。
- 保持长任务与实时对话协调，支持进度、打断和取消。

具体权限与交互在该版本需求阶段确认，不由首版监听或 Skill 导入权限自动推导。

## 6. v0.4 及以后：输入与平台扩展

- 屏幕、窗口文字、截图等更多电脑信息输入。
- 非语音声音事件识别，以及多个指定程序同时监听。
- 根据需求适配其他 Windows 版本、macOS 和 Linux。
- 更多桌宠形象、动作、表现方式和技能分发能力。
- 根据后续需求评估定时提醒与持久化日程，首版保持不实现。

## 7. 每个阶段的交付记录

阶段结束应更新已交付行为、验证证据、未解决问题、资源／时延测量、设计变化和下一步范围。优先顺序为：数据与输入正确性、核心交互可靠性、时延与成本、桌宠表现扩展。
