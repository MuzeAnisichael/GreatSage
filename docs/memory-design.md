# GreatSage 记忆、上下文与删除设计

更新日期：2026-10-01。本文描述 v0.2 alpha 的实现，并标出 v0.3 新增（已合入 main，尚未发版）的资料、产物和任务数据。使用方法见 [usage.md](usage.md)。

## 1. 数据模型与来源身份

运行目录中的 `memory.sqlite3` 使用 SQLite WAL、事务与线程锁保存数据。每条记录有独立 ID，时间为 UTC。消息修正生成新 ID，不在原 ID 上静默改写内容。

| 数据 | 当前职责与字段 |
| --- | --- |
| sessions | 会话 ID 与创建时间；每次启动或点击新会话创建一项 |
| messages | role、text、source、session_id、trace_id、时间与 metadata |
| memories | 用户显式记忆、来源 ID、版本和 revision_of；origin=user_explicit |
| summaries | 摘要文本、来源 ID、模型、模板版本、时间覆盖范围、原文／摘要字符数 |
| dependencies | 消息、摘要和记忆之间的派生关系，用于级联删除与失效处理 |
| events | 决策、来源、配置版本、模型调用、耗时、用量和错误等审计事件 |
| FTS5 索引 | 从有效消息建立全文检索；中文另做关键词／子串补充 |
| memory_conflicts | 新候选与可能矛盾的 active 记忆 ID；用户选择前状态为 pending |
| vectors、vector_records | 模型版本、内容哈希、片段向量及记录索引完成标记 |
| request_snapshots | 不可变配置/请求哈希、实际 Skill 版本、来源、可选正文与运行结局 |
| materials、material_chunks（v0.3） | 资料路径、内容哈希、版本和状态；片段的标题路径、行号、正文和哈希，另有 FTS5 索引 |
| artifacts、artifact_versions、citations、todos（v0.3） | 产物和每个版本的 Markdown；`[S#]` 标记对应的来源、摘录和有效状态；可编辑的待办行 |
| tasks、task_steps、tool_calls（v0.3） | 任务状态、步骤结果与耗时；工具调用的参数、效果、授权决策、审批方式、结果和撤销信息 |

麦克风和手动文本保存为 `user`，桌面声音为 `observation`，模型文字为 `assistant`。历史和观察资料进入模型时明确标注为参考数据；它们不能自动改变全局设置或变成已确认的用户偏好。

临时转写仅用于界面更新，不作为稳定消息持久化。最终转写记录音源、ASR 模型及语音结束时间。被打断的模型回答保留已经发出的文字并标记 `complete=false`，不假定这些文字已经全部被播报。

## 2. 长期记忆与跨会话恢复

持久记忆只有两种创建入口：用户在记忆页面手动添加，或用户文本／麦克风中出现明确的“记住”指令。后一种记忆引用原始用户消息；手动添加的记忆可以没有历史来源。

例如“记住：我喜欢简短回答”保存“我喜欢简短回答”，并关联这次输入。普通“我喜欢简短回答”仍会保存在历史，但不自动升级为显式记忆。助手和媒体说“记住……”也不会创建用户记忆。

重启和新会话保留数据库。新回答组合当前会话近期原文、相关持久记忆、历史检索和有效摘要；旧会话不冒充当前对话。冲突检测最多选择 24 条词法相关/近期记忆，在请求预算内进行限时结构化判断；模型只能提供 supplied ID 建议，不能自动覆盖。pending 候选不参与记忆或向量检索。用户选择替换、丢弃或共存后事务提交；没有任意事实自动提取或统一事实置信度体系。

## 3. 检索与上下文预算

检索保留 FTS5 和中文短语/双字词匹配。启用语义检索后调用 OpenRouter/OpenAI 兼容 `/embeddings` 或 Ollama `/api/embed`，本地保存归一化 float32 向量，按余弦排序并与词法结果进行 reciprocal-rank fusion。源 ID 和内容哈希在提交时重新校验；模型版本与维度不混用，删除/修正同时清理向量。

构建回答上下文时：

1. 先放入强制行为边界、输出语言、全局 Prompt 和当前输入；主动模式的判断前缀也计入预算。
2. 为启用且相关的 Skills 留出有限空间，记录实际注入的版本和文本截断状态。
3. 优先分配近期对话，再为显式记忆、摘要和检索原文分配空间；近期记录按时间顺序呈现。
4. 去重来源、标记被截断的参考资料，并用剩余空间补充其他有效记录。

`MemoryStore.context()` 控制序列化字符预算；Runtime 使用适用且已准备的 tokenizer 或保守 UTF-8 字节上界检查最终 messages，包含格式、转义和说明前缀。额外保留输出与协议余量。模型编码不可推断时不会自动下载或假设精确计数；当前输入或强制系统指令本身过长时明确报错，不静默裁掉。

调用日志记录实际采用的来源 ID、Skill 版本、配置版本与输入字节数。姓名、日期、金额、数字和原话等精确信息应尽量回查原文；摘要不能替代不存在的精确引文。

## 4. 后台压缩

当前会话保留最近 8 条消息作为压缩保护区。其余未覆盖原文达到至少 6 条时，后台任务尝试取最多 16 条，按最终请求预算选择可容纳的片段，并调用当前配置的 LLM 生成摘要。

后台压缩只发送精简的 `id/role/source/text` 字段，不把任意 metadata 整包带给模型。提示优先保留准确姓名、代码、数字及其对应关系，再保留偏好、未决事项和不确定性，区分用户、助手和媒体说法。完整来源 ID 在依赖图中独立保存，不让摘要正文反复抄写 ID 消耗输出预算；正文最多 768 tokens，且受用户配置的输出上限约束。

- 压缩不删除原文，也不自动创建显式用户记忆。
- 有前台回复或正在说话时优先让出资源；新请求可取消后台压缩。
- 纯旁听即使一直没有助手回复，也会在空闲时触发压缩。
- 保存摘要前再次检查来源是否存在且未被替代；删除期间返回的旧结果不能提交。
- 同一来源集合重复提交复用既有摘要；失败保留原文与已有有效摘要。
- 旧会话剩余至少 2 条未覆盖原文即可续压缩。未被父摘要覆盖的同级摘要达到 4 条时，取最多 8 条并按预算合并，自动调度到第 3 层，支持跨会话覆盖。

切换会话时取消进行中的压缩，空闲时从最早的待处理会话继续。低于阈值或放不进预算的原文保持可检索。摘要可能遗漏事实，必须保留原文和依赖图；重启、来源级联删除、有限批次与失败退避均不依赖内存任务队列。

## 5. 修正与删除语义

| 操作 | 数据变化 |
| --- | --- |
| 修正原文 | 创建新消息 ID，记录 revision_of；旧消息、依赖它的摘要／记忆／助手回答及旧索引被移除 |
| 修正记忆 | 创建新记忆 ID 和递增版本；旧记忆及其依赖回答失效 |
| 删除记忆 | 删除该记忆与派生内容；原始历史来源保留 |
| 删除原文 | 递归删除引用它的摘要、记忆和助手回答；移除检索索引并处理对应录音 |
| 清空历史 | 清除消息、会话、摘要、历史派生记忆、详细事件和录音；保留无来源的独立显式记忆。v0.3 起保留资料和产物，但指向原文的引用失效，任务中间正文和含正文的工具参数被清除 |
| 重新扫描到资料修改（v0.3） | 生成新版本和新片段；旧片段、引用它的回答和索引被移除，引用它的产物标为“来源已变更” |
| 移除资料（v0.3） | 删除全部片段、索引和引用它的回答；产物正文保留，对应引用失效 |
| 删除产物（v0.3） | 删除全部版本、引用表和待办；资料和原文不受影响 |

修正在一个数据库事务内完成；写入失败时原记录与依赖关系一起回滚。旧 ID 不再有效，因此后台任务不能用旧来源把被改正的摘要恢复回来。

删除和修正前，Runtime 中止相关回复、压缩与音频识别，更新会话／删除代际，清空相关缓存。排队的旧音频、取消后迟到的 ASR 和旧模型输出不能成为删除后的新历史。助手回答保存实际上下文的来源 ID，因而也能跟随来源删除。

事件一般通过 ID 引用来源；已有事件若含被删除的正文、依赖 ID 或关联 trace，会脱敏该事件内容。SQLite 启用安全删除，并清理全文索引和 WAL。该机制针对应用管理的本地数据，不保证删除用户另行复制的文件、系统备份或云端服务记录。

**产物不跟随来源一起删除**。纪要和文档是你要审阅、修改和导出的成果，删除资料或原文不会让它们消失。v0.3 把失效来源对应的引用标为无效并清除摘录，把产物标为“来源已变更”，由你决定重新生成、手动修改还是删除。已经导出到应用外的 `.md` 副本不在应用的删除范围内。任务成功后，步骤中暂存的来源正文会被清除，只保留产物和调用元数据。

**删除记忆不等于删除事实的所有来源。** 如果原文仍在，模型仍可能从历史得知相同内容。要移除该内容，需要同时删除相关原文；配置或外部 Skill 中独立存在的相同文字也不属于记忆删除的范围。首版没有自动重新提取任意历史事实的后台任务。

## 6. 审计边界

摘要保留来源、模型、模板和覆盖时间；回答记录注入的消息／摘要／记忆及技能配置。播放回执与生成完成是不同事件，不能将“生成成功”解释成“用户已听完”。审计不读取或依赖模型内部思维链。

配置日志默认记录哈希，Skill 记录实际版本；启用完整请求快照后，语言模型的 messages 和配置保留在本地，包含当时实际注入的 Skill 文本。源文删除使相关快照正文失效，导出需显式选择是否含正文。没有事先开启归档的请求无法补回旧正文，也不能保证外部模型输出完全复现。

转写、对话、摘要与记忆保留到手动删除；详细事件默认 30 天，开启后的原始录音默认 7 天。没有录音时，只能审计转写之后的处理过程，不能仅凭转写证明当时听写无误。

## 7. 回归重点与后续优化

回归覆盖跨会话恢复、中文检索、来源身份、删除与后台提交竞争、级联摘要／回答失效、修正回滚、上下文预算和显式记忆写入。实际测试数量与端到端结果见发布时的验证记录。

后续优先评估更大规模的混合检索、自然会话冲突漏检、复杂事实关系保持与长时间资源使用。当前小型固定集成绩、API 连通和源图正确性不能替代这些质量测量。
