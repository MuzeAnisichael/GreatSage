# GreatSage 记忆与上下文压缩设计草案

更新日期：2026-09-04。

## 1. 需求状态

已确认：长期记忆、跨会话记忆、近期原文、较早摘要、历史检索、用户偏好和显式记忆、来源追溯、查看／删除／清空记忆，以及上下文压缩。

以下数据结构、压缩方式和验证方法属于候选设计。数据库、嵌入模型、压缩模型、预算阈值和保存期限尚未定案。

## 2. 数据职责

| 数据 | 作用 | 关键属性 |
| --- | --- | --- |
| 近期原文 | 为当前对话提供准确、连续的局部上下文 | 记录 ID、会话、音源、起止时间、转写版本、临时／稳定状态 |
| 历史原文 | 供跨会话检索、核对细节和回查来源 | 原始转写与修订关系、用户输入、助手实际输出、来源引用 |
| 分段／会话摘要 | 压缩较早上下文，帮助定位相关历史 | 覆盖来源、时间区间、版本、生成配置、状态 |
| 持久记忆 | 保存偏好、明确要求记住的事实和事项 | 内容、来源、创建／生效时间、状态、修订与替代关系 |
| 全局配置 | 管理用户设定的 Prompt、预设及 Skills | 配置版本、适用范围、启用状态 |
| 审计事件 | 解释系统当时接收、选择、调用和输出了什么 | 关联 ID、引用记录、配置版本、结果、耗时、错误 |

全局配置由用户设置路径管理，后台摘要不能修改它。助手输出和媒体中的说法保留各自来源身份，不能自动变成已证实的用户事实或用户指令。

## 3. 记忆写入建议

- 稳定转写进入历史记录，临时转写继续带修订状态；避免把识别中的半句话永久固化。
- 用户明确要求记住的信息写入持久记忆，并保留原始来源。
- 自动提取的信息区分“候选记忆”和“已生效记忆”；自动生效范围需在预设设计中明确。
- 用户的明确纠正产生修订／替代关系，不静默抹掉来源差异。
- 对有冲突且无法判定的记录保留冲突状态，回答时结合来源和时间说明不确定性。
- 用户打断后，历史区分模型生成内容、已经显示的内容和实际播报范围，避免假定用户听过未播放的回答。

## 4. 分层压缩

候选流程：原文片段 → 分段摘要 → 会话摘要。先采用可追溯的分层摘要，后续依据检索效果评估更复杂的记忆结构。

每个摘要至少保存：

- 摘要 ID、版本和生成状态。
- 覆盖的原文片段 ID、修订版本、时间区间与音源。
- 压缩所用模型、模板和配置版本。
- 原始／摘要 token 数或估算值，并注明计数方式。
- 关键事实、偏好、事项、未决问题与冲突。
- 关键事实的原始来源引用；上层摘要的引用应能继续追到原始转写。

压缩用于缩减进入模型的上下文，不自动删除历史原文。数据到期或用户删除的行为由独立保存策略控制。

涉及姓名、日期、数字、原话和其他需要精确性的回答，优先检索原始记录核对。检索不到有效原文时，应明确当前依据来自摘要，避免伪造精确引用。

后台任务生成新摘要后，检查来源是否仍存在、版本是否变化、引用是否有效。只有有效结果才能成为当前摘要；过时结果丢弃或重新生成。

## 5. 上下文预算

每次调用按当前模型和服务的实际可用上下文构建预算，并预留输出容量与计数误差。

建议优先顺序：

1. 生效的全局指令、预设和适用 Skills。
2. 当前输入及理解当前轮次所必需的近期原文。
3. 与当前问题相关的持久记忆、历史原文和摘要。

每份来源在一次调用中去重，避免同一事实以原文、分段摘要和会话摘要反复占用预算。记录实际注入的来源及摘要版本，使上下文选择可审计。

达到压缩阈值时启动异步任务。压缩未完成时，优先使用已有有效摘要和预算内的近期记录，并按相关性检索历史。若当前输入或必需配置本身超过模型容量，应显式处理或提示，不能静默丢弃关键指令。

模型切换后重新计算预算，不直接沿用原模型的上下文上限。检索、嵌入、压缩失败时记录降级情况，不把失败结果写成正常记忆。

## 6. 实时性与后台调度

- 前台语音交互优先于后台摘要和索引更新。
- 压缩任务限并发，并合并重复的覆盖区间。
- 本地模型、识别与合成可能竞争显存和计算资源，需要在本机分别测量。
- 任务支持取消、超时和重试；取消的任务不能提交部分结果为有效摘要。
- 压缩失败保留上一有效版本和仍在保存期内的原始记录。
- 记录后台压缩对首段文本、首段语音和打断延迟的影响。

## 7. 修正、删除与恢复

为摘要、持久记忆和索引记录来源依赖关系。

### 修正

用户纠正事实或转写时，创建新修订；将依赖旧版本的摘要、记忆和索引标记为失效或过时，重建后再用于新回答。明确的用户纠正优先更新对应记忆；媒体中的不同说法不能自动覆盖用户设置。

### 删除

- 提供查看、删除和清空入口。
- 明确区分“忘记一条持久记忆”和“删除该内容及其历史来源”；前者应防止后台提取立即重新生成同一条记忆。
- 删除原文时，同步删除其检索索引，删除或重建包含该内容的派生摘要与记忆。
- 缓存、包含正文的日志和应用管理的导出／备份应纳入删除范围设计；用户另外复制到应用外的文件无法由程序自动保证删除。
- 取消或作废引用已删除数据的后台任务，避免任务完成后恢复内容。
- 操作日志可以保留删除时间、操作类型和记录 ID，不重新复制已删除正文。

### 崩溃与重启

持久写入采用一致性机制，区分未完成任务与有效记录。重启恢复后，失效／已删除来源及未完成摘要不得重新进入上下文；索引重建以有效记录为依据。

## 8. 日志与记忆的关联

记忆用于后续回答；日志用于回查一次运行。建议日志通过 ID 引用来源，尽量减少相同个人内容的重复持久化。

每次模型调用关联：

- 输入、触发事件、生效配置和实际使用的记忆。
- 上下文组成、摘要版本、被选中的历史来源。
- 模型与服务、用量、各阶段耗时和结果。
- 输出显示／播放范围、打断、取消和失败。

准确重建一次调用需要保留对应版本的来源或受控的输入快照；具体保存方式应与删除和保留策略共同确定。任何审计副本中的内容也必须服从已确认的删除语义。

不依赖模型内部思维链作为审计材料。

## 9. 已确认的默认保存策略

用户已确认：持久保存转写、对话、摘要和记忆；运行日志按项目日志需求保存。原始音频默认仅作短时处理缓冲，需要回放或排障时可以手动开启本地录音保存。

默认审计可以回溯到带时间与音源标记的转写；手动开启录音后，可结合已保存的音频回放核对。仍需逐步明确：

- 手动开启录音后的保存期限。
- 转写／对话、详细运行日志、摘要和显式记忆各自的保存期限。

不保存原始音频时，审计可以追踪转写之后的处理过程，但无法仅凭文本验证系统当时是否听写正确。

## 10. 验收建议

- [ ] 保存偏好和有来源的事项后结束进程；重启后可恢复、正确使用并展示来源。
- [ ] 连续输入超过上下文预算后完成压缩；历史姓名、时间、数字仍可检索到原文。
- [ ] 摘要覆盖区间、引用和版本有效，临时转写修订不会成为过时的持久事实。
- [ ] 用户纠正后，新回答使用修正值；旧摘要不会继续提供过时事实。
- [ ] 删除内容后，搜索、摘要、缓存和重启后的回答不再返回该内容。
- [ ] 删除期间正在运行的压缩／提取任务不能使内容重新出现。
- [ ] 切换模型后，输入及输出预留保持在预算内。
- [ ] 后台压缩期间测量已确认实时目标，并记录延迟增量。
- [ ] 压缩超时、失败或中途退出后，未完成摘要不被当作有效记忆。
- [ ] 助手未播完的回答不会被记录为用户已完整听到。
