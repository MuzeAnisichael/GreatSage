# GreatSage 记忆、上下文与删除设计

更新日期：2026-10-24。本文描述包含 v0.6 结构化记忆的当前源码语义；版本、构建及验证状态见 [project-status.md](project-status.md)，已确认范围见 [v0.6-plan.md](v0.6-plan.md)。使用方法见 [usage.md](usage.md)。

## 1. 数据模型与来源身份

运行目录中的 `memory.sqlite3` 使用 SQLite WAL、事务与线程锁保存数据。每条记录有独立 ID，时间为 UTC。消息修正生成新 ID，不在原 ID 上静默改写内容。

| 数据 | 当前职责与字段 |
| --- | --- |
| sessions | 会话 ID 与创建时间；每次启动或点击新会话创建一项 |
| messages | role、text、source、session_id、trace_id、时间与 metadata |
| memories | 显式或提取记忆、来源 ID、版本、revision_of 和 status；origin=user_explicit/extracted，status=active/pending |
| structured_memories（v0.6） | memory_id 外键；事实／偏好／关系的 kind、subject、subject_type、predicate、value、object_type、evidence、review_reasons、model 与去重 fingerprint |
| memory_extraction_progress（v0.6） | 已处理来源 ID、内容哈希、处理时间和模型；与记忆提取同事务提交，来源删除时级联清理 |
| memory_extraction_blocks（v0.6） | 不再提取的旧来源 ID／内容哈希／时间；不存被拒绝或删除的正文，跨重启生效 |
| memory_extraction_deferred（v0.6） | 单条原文超预算时的来源 ID／哈希／预算版本／原因／时间；不是成功进度或遗忘，预算变化后可重试 |
| forgotten_memories | 显式删除记忆的 ID／来源 ID／时间；旧版本遗忘记录迁移到来源抑制表，不保留原记忆正文 |
| summaries | 摘要文本、来源 ID、模型、模板版本、时间覆盖范围、原文／摘要字符数 |
| dependencies | 消息、摘要和记忆之间的派生关系，用于级联删除与失效处理 |
| events | 决策、来源、配置版本、模型调用、耗时、用量和错误等审计事件 |
| FTS5 索引 | 从有效消息建立全文检索；中文另做关键词／子串补充 |
| memory_conflicts | 新候选与可能矛盾的 active 记忆 ID；用户选择前状态为 pending |
| vectors、vector_records | 模型版本、内容哈希、片段向量及记录索引完成标记 |
| request_snapshots | 不可变配置/请求哈希、实际 Skill 版本、来源、可选正文与运行结局 |
| materials、material_chunks（v0.3） | 资料路径、内容哈希、版本和状态；片段的标题路径、行号、正文和哈希，另有 FTS5 索引 |
| artifacts、artifact_versions、citations、todos（v0.3） | 产物和每个版本的 Markdown；`[S#]` 标记对应的来源、摘录和有效状态；可编辑的待办行 |
| tasks、task_steps、tool_calls（v0.3） | 任务状态、步骤结果与耗时；工具调用的参数、效果、授权决策、审批方式、结果和撤销信息 |

麦克风和手动文本保存为 `user`，桌面声音为 `observation`，模型文字为 `assistant`。历史和观察资料进入模型时明确标注为参考数据，不能改变全局设置或发起工具操作。自动提取仅接受 `role=user` 且来源为 `text`、`microphone` 或 `microphone:<device>` 的稳定原文；助手、工具、系统与桌面旁听不能成为提取的用户事实来源。

临时转写仅用于界面更新，不作为稳定消息持久化。最终转写记录音源、ASR 模型及语音结束时间。被打断的模型回答保留已经发出的文字并标记 `complete=false`，不假定这些文字已经全部被播报。

## 2. 长期记忆与跨会话恢复

持久记忆有显式添加和可选后台提取两条路径。用户在记忆页面手动添加，或用户文本／麦克风中出现明确的“记住”指令，继续沿用显式流程。后一种记忆引用原始用户消息；手动添加的记忆可以没有历史来源。

例如“记住：我喜欢简短回答”保存“我喜欢简短回答”，并关联这次输入。普通“我喜欢简短回答”先保存在历史；默认关闭自动提取时不自动升级为记忆。开启提取后，它可以形成带原文证据的候选或有效提取。助手和媒体说“记住……”不会创建用户记忆。

重启和新会话保留数据库。新回答组合当前会话近期原文、相关持久记忆、历史检索和有效摘要；旧会话不冒充当前对话。显式添加的冲突检测最多选择 24 条词法相关／近期记忆，在请求预算内进行限时结构化判断；模型只能提供 supplied ID 建议，不能自动覆盖。提取路径使用下述结构键检测，不额外把已有记忆交给 LangMem 更新。

### 三档提取生效策略

`memory_extraction_enabled=false` 是默认值；启用后使用当前聊天模型与已有凭据，云端服务会收到相应原文。`memory_confirmation` 默认 `mostly`。修改设置只影响后续提取，不批量批准既有候选，也不撤销已经生效的记忆。

| 设置值／界面名称 | 普通对话提取的处理 |
| --- | --- |
| auto／自动生效 | 通过来源与 schema 校验后生效；检测到结构冲突仍为 pending |
| necessary／仅必要时确认 | 冲突，或模型标出 uncertain、sensitive、ambiguous_entity 时为 pending；其余生效 |
| mostly／大部分确认 | 全部普通提取为 pending；明确“记住”和手动添加继续走显式流程 |

不确定、敏感和归属含糊标记来自提取模型，不是独立的事实审核或敏感内容识别保证；没有统一事实置信度体系。

### 候选、冲突与实体

`active` 才参与长期记忆及向量检索；`pending` 可在候选与实体详情中查看，但不注入回答。无冲突候选可接受或拒绝；接受时再次检查当前有效记忆，避免先批准候选 A 后，仍把与 A 冲突的 B 直接生效。有冲突时保留旧记忆并复用替换／丢弃新候选／共存入口。拒绝或删除会移除候选及结构正文；API 的 `rejected` 是决策结果，不是保留正文的第三种存储状态。

提取的冲突规则为：有效结构记录的 `(subject, subject_type, predicate)` 精确相同，但 `value` 或 `object_type` 不同。它不能普遍识别旧纯文本记忆的矛盾，也不能理解所有同义属性、多值关系、时间变化或自然语言否定。不同写法可能漏检，同一属性的合理多值也可能被提示冲突；裁决保留给用户。

实体不是独立图数据库对象，而是结构记录的投影视图：主体和非 literal 客体按精确 `(name, type)` 生成稳定 ID、统计有效／待确认数量。不同大小写、别名和相似拼写不自动合并；**相同名称与类型会进入同一组，但不表示已证明是同一个人或完成消歧**。实体详情分开呈现事实／偏好与关系，显示状态和原文依据；修改、删除使用既有记忆入口。

### 证据及存储校验

模型只返回 `MemoryFact` 提案，不能指定记忆 ID、来源版本、存储状态或调用业务工具。每项必须携带本批来源的 `source_id` 与非空逐字连续 `quote`。存储层重新核对来源的 ID、正文、内容哈希、版本、角色、音源和会话，再为证据填入可信的哈希／版本；伪造来源、引用不匹配或旧快照使整批失败，处理进度不前移。

逐字匹配只能确认引文存在于给定原文，**不能证明提取结论由引文推出或事实本身正确**。问题、假设、第三方转述和指令虽被提示排除，仍可能被模型误解。界面标为用户自述／派生信息并展示原文证据，用户应结合上下文判断。

## 3. 检索与上下文预算

检索保留 FTS5 和中文短语/双字词匹配。启用语义检索后调用 OpenRouter/OpenAI 兼容 `/embeddings` 或 Ollama `/api/embed`，本地保存归一化 float32 向量，按余弦排序并与词法结果进行 reciprocal-rank fusion。源 ID 和内容哈希在提交时重新校验；模型版本与维度不混用，删除/修正同时清理向量。

构建回答上下文时：

1. 先放入强制行为边界、输出语言、全局 Prompt 和当前输入；主动模式的判断前缀也计入预算。
2. 为启用且相关的 Skills 留出有限空间，记录实际注入的版本和文本截断状态。
3. 优先分配近期对话，再为有效长期记忆、摘要和检索原文分配空间；近期记录按时间顺序呈现。
4. 去重来源、标记被截断的参考资料，并用剩余空间补充其他有效记录。

`MemoryStore.context()` 控制序列化字符预算；Runtime 使用适用且已准备的 tokenizer 或保守 UTF-8 字节上界检查最终 messages，包含格式、转义和说明前缀。额外保留输出与协议余量。模型编码不可推断时不会自动下载或假设精确计数；当前输入或强制系统指令本身过长时明确报错，不静默裁掉。

调用日志记录实际采用的来源 ID、Skill 版本、配置版本与输入字节数。姓名、日期、金额、数字和原话等精确信息应尽量回查原文；摘要不能替代不存在的精确引文。

`MemoryStore.list_memories()` 和 `record()` 为有效提取附加 `structured.evidence`；这些字段随实际选入上下文的记忆保留，并计入同一预算。候选不会因实体浏览或向量索引而绕过 active 筛选。删除记忆后，其仍保留的用户原文可以独立进入近期或历史检索，不能把“候选不注入”理解为“原文也不可检索”。

## 4. 后台压缩与提取

当前会话保留最近 8 条消息作为压缩保护区。其余未覆盖原文达到至少 6 条时，后台任务尝试取最多 16 条，按最终请求预算选择可容纳的片段，并调用当前配置的 LLM 生成摘要。

后台压缩只发送精简的 `id/role/source/text` 字段，不把任意 metadata 整包带给模型。提示优先保留准确姓名、代码、数字及其对应关系，再保留偏好、未决事项和不确定性，区分用户、助手和媒体说法。完整来源 ID 在依赖图中独立保存，不让摘要正文反复抄写 ID 消耗输出预算；正文最多 768 tokens，且受用户配置的输出上限约束。

- 压缩不删除原文，也不自动创建显式用户记忆。
- 有前台回复或正在说话时优先让出资源；新请求可取消后台压缩。
- 纯旁听即使一直没有助手回复，也会在空闲时触发压缩。
- 保存摘要前再次检查来源是否存在且未被替代；删除期间返回的旧结果不能提交。
- 同一来源集合重复提交复用既有摘要；失败保留原文与已有有效摘要。
- 旧会话剩余至少 2 条未覆盖原文即可续压缩。未被父摘要覆盖的同级摘要达到 4 条时，取最多 8 条并按预算合并，自动调度到第 3 层，支持跨会话覆盖。

切换会话时取消进行中的压缩，空闲时从最早的待处理会话继续。低于阈值或放不进预算的原文保持可检索。摘要可能遗漏事实，必须保留原文和依赖图；重启、来源级联删除、有限批次与失败退避均不依赖内存任务队列。

提取与压缩共享 `_background_cycle` 的空闲调度和前台让出机制，但使用独立进度与退避状态。`extract_memories()` 一次至多选择 8 条未处理、未抑制的完整用户原文，按实际请求预算缩小批次；LangMem 单步返回至多 24 项，适配器最多发起一次模型请求，不在框架内部自动补问或重试。没有合适条目时，模型必须单独返回合法的 `NoMemory(no_memory=true)`，不能与 `MemoryFact` 混用；仅返回普通正文或没有 schema 调用视为失败，不将来源误记为已处理。有效的空结果会提交本批进度；失败不提交进度，后续按后台退避重试。因此所选 API／Ollama 模型需要支持这套结构化调用协议。

`plan_sources()` 先检查单条完整原文能否装入预算，不能装入的由 `defer_extraction_sources()` 记录为延后。`budget_version` 由模型、上下文／输出预算、提示／schema 和计数方式等条件生成，不含凭据或正文。同一预算下跳过这些来源，使前 8 条超长原文不会阻塞第 9 条短原文；仅因本批剩余空间不足而未选入的可容纳来源不被永久延后。延后既不是 processed，也不是遗忘；更换相关预算或修正来源后可再次尝试，原文始终可检索。

`POST /api/memory/extraction` 只安排当前会话的一批提取并立即返回状态，开关关闭时拒绝发送历史。开启后，常规后台周期可继续处理未完成的旧会话来源；已处理或已抑制的来源不会因重启反复扫描。状态接口与 `memory_extraction` 事件只提供阶段、计数、模型和安全错误，候选正文及引用通过记忆详情读取。运行阶段包括 disabled、queued、running、completed、failed、cancelled、discarded、deferred 和 idle；来源进度以 SQLite 为准，运行阶段不是持久化候选状态。`deferred_sources` 统计当前预算下延后的来源，仍属于尚未成功处理的来源。

运行身份包含 `epoch`、`data_epoch`、`generation`、`memory_extraction_epoch`、会话 ID 与设置版本。`pause_background()` 先提升提取代际再取消任务，收尾只作有界等待；不合作的旧提取继续占位，避免前台等待无限收尾或启动无限替代批次。请求前、模型返回后及提交前再次检查身份和来源，提交前检查与数据库事务之间没有异步让出。设置、会话、删除或前台请求使旧结果失效，即使取消后的提供商返回也不能提交。存储层不加载模型，LangMem 不持有数据库；完整调用关系见 [代码导航](code-map.md)。

## 5. 修正与删除语义

| 操作 | 数据变化 |
| --- | --- |
| 修正原文 | 创建新消息 ID，记录 revision_of；旧消息、依赖它的摘要／记忆／助手回答及旧索引被移除 |
| 修正记忆 | 创建新记忆 ID 和递增版本，作为用户显式修正；旧结构／证据及依赖回答失效，不把模型旧结构当作修正后仍然成立；旧来源写入提取抑制 |
| 删除记忆／拒绝候选 | 删除该记忆、结构正文与派生内容；原始历史来源保留，旧来源版本写入提取抑制 |
| 删除原文 | 递归删除引用它的摘要、有效／待确认记忆和助手回答；级联删除结构／提取进度，移除检索索引并处理对应录音 |
| 清空历史 | 清除消息、会话、摘要、历史派生记忆、详细事件和录音；保留无来源的独立显式记忆。v0.3 起保留资料和产物，但指向原文的引用失效，任务中间正文和含正文的工具参数被清除 |
| 重新扫描到资料修改（v0.3） | 生成新版本和新片段；旧片段、引用它的回答和索引被移除，引用它的产物标为“来源已变更” |
| 移除资料（v0.3） | 删除全部片段、索引和引用它的回答；产物正文保留，对应引用失效 |
| 删除产物（v0.3） | 删除全部版本、引用表和待办；资料和原文不受影响 |

修正在一个数据库事务内完成；写入失败时原记录与依赖关系一起回滚。旧 ID 不再有效，因此后台任务不能用旧来源把被改正的摘要恢复回来。

删除和修正前，Runtime 中止相关回复、压缩、提取与音频识别，更新会话／删除代际，清空相关缓存。排队的旧音频、取消后迟到的 ASR 和旧模型输出不能成为删除后的新历史。助手回答保存实际上下文的来源 ID，因而也能跟随来源删除。

事件一般通过 ID 引用来源；已有事件若含被删除的正文、依赖 ID 或关联 trace，会脱敏该事件内容。SQLite 启用安全删除，并清理全文索引和 WAL。该机制针对应用管理的本地数据，不保证删除用户另行复制的文件、系统备份或云端服务记录。

**产物不跟随来源一起删除**。纪要和文档是你要审阅、修改和导出的成果，删除资料或原文不会让它们消失。v0.3 把失效来源对应的引用标为无效并清除摘录，把产物标为“来源已变更”，由你决定重新生成、手动修改还是删除。已经导出到应用外的 `.md` 副本不在应用的删除范围内。任务成功后，步骤中暂存的来源正文会被清除，只保留产物和调用元数据。

**删除记忆不等于删除事实的所有来源。** 如果原文仍在，模型仍可能从历史得知相同内容。要移除该内容，需要同时删除相关原文；配置或外部 Skill 中独立存在的相同文字也不属于记忆删除的范围。

v0.6 在删除／拒绝／修正旧记忆时记录叶子原文的 ID 和内容哈希，启动时也将旧 `forgotten_memories` 的来源迁入抑制表。抑制不保存被删除的正文，重试、重启或模型换一种措辞都不能从这些旧来源重新生成提取。

这里采用**旧来源版本整体抑制**：删除某条提取后，同一条旧原文中其他尚未提取的事实也不会自动补提取；一项有多个来源时，涉及的旧来源均受抑制。抑制本身不删除仍有效的其他记忆。这是避免改写绕过遗忘的保守取舍，尚未做到逐事实语义遗忘。新输入或修正原文产生新 ID／版本，可形成新的提取；用户明确重新添加也允许建立新记忆。清空历史时同时移除处理进度与抑制表，原文已不存在，旧快照仍无法通过存储复核。

## 6. 审计边界

摘要保留来源、模型、模板和覆盖时间；回答记录注入的消息／摘要／记忆及技能配置。播放回执与生成完成是不同事件，不能将“生成成功”解释成“用户已听完”。审计不读取或依赖模型内部思维链。

提取复用本地请求快照与用量事件，保存实际发送的来源身份；LangMem 远端追踪、自动提示优化与远端存储不启用。默认监控只含提取数量、阶段、模型与安全错误；启用请求正文归档仍是独立选择，不能因为开启提取而自动开启。

配置日志默认记录哈希，Skill 记录实际版本；启用完整请求快照后，语言模型的 messages 和配置保留在本地，包含当时实际注入的 Skill 文本。源文删除使相关快照正文失效，导出需显式选择是否含正文。没有事先开启归档的请求无法补回旧正文，也不能保证外部模型输出完全复现。

转写、对话、摘要与记忆保留到手动删除；详细事件默认 30 天，开启后的原始录音默认 7 天。没有录音时，只能审计转写之后的处理过程，不能仅凭转写证明当时听写无误。

## 7. 回归重点与后续优化

既有回归覆盖跨会话恢复、中文检索、来源身份、删除与后台提交竞争、级联摘要／回答失效、修正回滚、上下文预算和显式记忆写入。v0.6 定向用例位于 [test_structured_memory.py](../tests/test_structured_memory.py)、[test_memory_extraction.py](../tests/test_memory_extraction.py)、[test_memory_runtime.py](../tests/test_memory_runtime.py)、[test_server.py](../tests/test_server.py) 和[桌面冒烟](../scripts/smoke_desktop.cjs)，涉及三档策略、伪造证据、冲突再检查、旧来源抑制、跨重启、异步失效及界面操作。测试存在不代表所有环境已经通过，实际结果见当前版本验证记录。

后续优先评估更大规模的混合检索、自然会话提取／冲突漏检、同名实体归属、复杂关系保持与长时间资源使用。当前小型固定集成绩、API 连通、逐字引文和来源图正确性不能替代这些质量测量。

确定性提取错误立即进入 `needs_attention`；暂时性错误最多尝试三次（含首次）后暂停。安全错误码与设置版本保存到运行目录 `memory-extraction-state.json`，同配置下重启保持暂停；手动提取、后台重试或配置更新可恢复。
