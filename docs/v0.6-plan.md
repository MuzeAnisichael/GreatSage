# v0.6 结构化记忆与实体

确认日期：2026-10-23。用户确认完成 v0.6 并交付 main，新增三档记忆生效设置。基线为 v0.5 alpha / `ed63006`，沿用 API 优先、Ollama 兼容、小切片与必要验证；性能数值不作为完成前提。

## 范围与默认行为

1. 复用 LangMem 的结构化提取能力，GreatSage 继续管理本地持久化、来源版本、冲突和删除。提取只读模型输出，不能直接调用存储或工具操作。
2. 设置提供独立的“自动提取记忆”开关和三档策略，默认关闭自动提取、默认策略“大部分确认”。启用后使用当前聊天模型和已有凭据，界面说明后台模型调用；支持手动提取当前会话及继续后台处理。
3. **自动生效**：有效提取直接生效，但与已有记忆的明确冲突仍待裁决，不覆盖旧记忆。**仅必要时确认**：另外对不确定、敏感或实体归属含糊的候选要求确认。**大部分确认**：普通对话提取全部进入候选；明确“记住”及手动添加仍沿用现有流程。设置变更不自动批准已有候选。
4. 首轮只从稳定的用户文字／麦克风原文提取；助手、工具、系统和桌面旁听不自动成为用户事实。提取候选必须有可定位的原文证据；输出作为用户自述／派生信息，不能当作独立验证事实。
5. 记忆界面提供候选确认／拒绝、事实与偏好、实体和关系浏览、来源详情、修改／删除；回答检索只使用有效记忆，保留实际来源证据。实体按明确名称和类型归组，不自动模糊合并同名人或不同别名。
6. 删除或拒绝后，同一旧来源版本不能经重试、重启或重扫恢复该条提取。保留原文仍允许历史检索得知同一事实，删除记忆与删除原文需要明确区分。新来源或用户明确重新添加仍可形成新记忆。

## 实施接口约定

该段用于并行实现的文件分工与稳定接口，最终实现变动同步到代码导航。

- 设置：`memory_extraction_enabled: bool = false`，`memory_confirmation: auto | necessary | mostly = mostly`。
- 提取结构：`text`, `kind`（fact/preference/relationship）, `subject`, `subject_type`（person/project/organization/other）, `predicate`, `value`, `object_type`（literal/person/project/organization/other）, `evidence: [{source_id, quote}]`, `review_reasons`（uncertain/sensitive/ambiguous_entity）。事实 ID、来源版本、状态与确认原因由存储层生成，不由模型指定。
- 存储入口：`extraction_sources(limit=8, session_id=None)`；`save_extraction(items, sources, policy, model)` 返回保存结果／数量；`memory_candidates_list()`；`resolve_memory_candidate(id, action)`（accept/reject，冲突使用原冲突裁决入口）；`memory_entities(query='')`；`memory_entity(id)`；`extraction_status()`。存储层对来源和证据再次核验，提取检查点与候选同事务落盘。
- API：`GET /api/memory/candidates`，`POST /api/memory/candidates/{id}/resolve`，`GET /api/memory/entities?q=`，`GET /api/memory/entities/{id}`，`GET /api/memory/extraction`，`POST /api/memory/extraction`。既有记忆修改／删除、来源及冲突接口继续有效。
- 运行入口：`Runtime.extract_memories()` 为后台单批；`Runtime.request_memory_extraction()` 返回已安排状态，不阻塞 HTTP 等待模型。手动提取也要求开关启用，避免在未选择提取时发送历史。复用现有后台让出／退避，禁止隐式全库反复扫描；取消、设置改变、会话改变和删除后拒绝旧结果。
- 事件使用 `memory_updated` 和 `memory_extraction`；状态只含数量、阶段和安全错误，不在监控默认暴露正文。

## 验证与交付

覆盖三档策略、非法／伪造证据、候选与冲突、删除后重启防复生、旧异步结果、实体关系与检索证据。复用已有测试和 CI，不重复历史全量本地回归；按需要做一次有界真实 API／Ollama兼容检查，说明模型支持限制。最终冻结一次并检查发布对象，更新开发日志、结构图、函数导航、记忆设计及已知限制，保留切片合入 main。

LangMem 官方参考：[结构化提取](https://langchain-ai.github.io/langmem/guides/extract_semantic_memories/)、[函数接口](https://langchain-ai.github.io/langmem/reference/memory/)。选用固定版本并在实现时核对其依赖、重试与追踪行为；不启用自动提示改写或远端记忆服务。产品多 Agent 仍属 v0.7。
