# GreatSage 使用说明

本文对应 v0.6 alpha；版本与下载见[项目现状](project-status.md)。先按 [README](../README.md) 启动应用；首次默认不监听、不播报、不保存录音，自动提取记忆、语义索引和全文请求归档也默认关闭。ZIP 可直接解压试用；NSIS 为实验性安装器，人工安装链尚未验收。

## 1. 配置与开始聆听

在“设置”中分别配置语音识别、语言模型和语音合成。三者可以使用不同服务：例如 API 识别与语言模型搭配本地系统语音，或本地识别搭配云端语言模型。

保存后分别测试连接。测试通过只说明该配置在测试样本上返回了结果；它不等于所有语言、音源或低延迟目标都已通过验收。选择本地识别时，先安装可选依赖并使用准备模型入口；实际开始监听不应自动下载权重。

API 密钥可从环境变量读取，也可输入到设置中加密保存。同一服务和账号下，密码框留空会保留之前的密钥；更换服务、地址或密钥环境变量时会清除该组件的旧密钥，请提供目标服务的新密钥。单独清除本地密钥后仍可能使用其环境变量；需要完全取消时同时清空该组件的环境变量名。

v0.5 新增可选 **Deepgram 流式识别**：选择后保持官方地址，使用 `nova-3`，语言设为 `zh`、`zh-TW`、`en` 或 `ja`，配置独立 `DEEPGRAM_API_KEY` 或新密钥后保存。“测试连接”只建立并关闭鉴权连接，不发送音频；按“开始聆听”后才发送所选音源。它与聊天、TTS 分开计费，当前未完成本机真实服务质量／费用比较，不自动注册或购买服务。

流式稳定片段不等于整句话结束。短暂停顿后可以继续说话，不必等上一句识别完成；应用按顺序保存已确认内容，在你说完且该音源的待确认内容处理完后，再按预设决定是否回应。流式识别最多保留四个较早的待确认话轮加当前轮次；断流、积压、队列已满、无法判断内容属于哪一轮，或一句话本地结束后 15 秒仍未确认时，才会停止该音源。这些连续语音行为尚未完成真实设备与 Deepgram 服务验证。

首页“音源状态”区分“正在听你说话”“正在确认转写”和“等待语音”，并显示待确认段数；等待确认时可以继续说话。实时转写分别标明“识别中，文字可能调整”和“已确认”，上一句迟到的结果不会覆盖下一句。停止或失败后的临时文字标为“未完成，未提交”，需要恢复后重新说；切换会话会清空实时转写列表。首页和运行监控会保留失败原因及操作入口：

- **重试此音源**：仅重建失败的识别连接，其他音源继续；只接收重试后的新音频，丢弃旧缓冲，不补发刚才未完成的话。可在恢复后重新说一遍。
- **检查音源**：设备或进程采集已经停止；检查连接或程序，暂停聆听、刷新来源，必要时重新选择当前设备／PID，再开始聆听。
- **打开识别设置**：修正缺失密钥或不支持的配置，保存后按当前状态重新开启监听。

不会自动重连、重放或切换服务。原 API／本地分段识别继续可选。录音默认关闭；开启后，超出最长分段缓冲的流式话轮会跳过录音并记录原因，避免保存残缺音频。

“运行监控 → 语音管线与播放反馈”显示音源状态、积压与失败原因，以及四项独立耗时。起播／停止回执包含传递时间，不能视作声卡实测；没有记录时显示“待测”。

在“对话与感知”选择：

- 是否启用麦克风，以及使用哪个设备。
- 桌面音源：不监听、系统整体或一个指定程序。
- 需要指定程序时，先刷新程序列表再选择；程序重启后 PID 可能改变。

点击“开始聆听”后观察来源转写和运行状态。桌面声音与麦克风分别标记；同一句话的临时识别可能修订，稳定结果才进入会话原文。暂停聆听停止采集，重新启动不会恢复旧队列中的音频。

## 2. 选择秘书行为

| 预设 | 默认行为 | 例子 |
| --- | --- | --- |
| 对话伙伴 | 麦克风说完后回答；桌面内容作为背景 | 直接对麦克风提问 |
| 旁听助手 | 收集内容；在麦克风明确提问、叫名或发出请求时回答 | “大贤者，刚才讲了什么？” |
| 主动秘书 | 开启允许主动回应后，结合全局指令判断是否插话 | 关注正在讨论的风险，必要时简短解释 |

手动输入文字始终视为直接请求。旁听对明确叫名和请求使用快速路径；含糊提问和转述交给当前语言模型，最多等待 3 秒，失败时保持安静并记录原因。设置中可以关闭“旁听语义判断”并使用规则结果。该模型需要支持结构化输出；慢速本地模型可能超时，需要明确叫名或关闭语义判断。

全局指令可描述角色、关注点、表达方式和主动回应条件。例如：

> 回答尽量简短。旁听时关注讨论中的方案、结论和未决事项。只有信息确实有帮助时才插话，不需要回应每句背景对话。没有可靠依据时说明不确定。

明确设置优先于这段指令：关闭允许主动回应时，不会仅因 Prompt 提到“主动提醒”就绕过开关。应用不会设置闹钟。v0.2 不执行电脑操作；v0.3 的操作都要经过授权，见第 10 节。

## 3. 文字、语音和桌宠

设置输出语言和是否播报。文字与语音语言不同时，语音文本可能额外调用语言模型翻译，会增加时延与调用量。

语音按片段生成并排队播放。你可以使用打断入口或在麦克风中开始说话；界面会取消未完成回复和待播语音。语音服务失败时保留文字，并在日志显示错误。已经显示的部分回答会保留，但不代表你已经听完。

控制台和桌宠跟随 Windows 的浅色／深色模式。在侧栏点击“显示桌宠”或“收起”控制桌宠窗口。显示桌宠后可拖动位置、进行摸摸互动并查看气泡与状态动画。主窗口关闭后可能收起到托盘；使用托盘退出才结束整个应用。若启用了桌宠鼠标穿透，可通过托盘恢复鼠标操作。

目前的自身声音抑制不是完整 AEC。麦克风不根据文字相似度丢弃用户复述，只使用保守声学判断；文字去重用于桌面音源。扬声器回流、噪声和重叠说话会影响识别；先使用耳机有助于更清楚地验证秘书行为。

## 4. 让信息跨会话保留

可以在聊天或麦克风中明确说：

- “记住：我喜欢简短回答。”
- “请记住我希望默认用中文解释。”
- “Remember that I prefer concise replies.”

这些指令会创建来源指向当前用户消息的长期记忆。也可以在“长期记忆”页面填写内容并点击“添加记忆”；手动添加的记忆没有历史来源。

显式添加的记忆会与相关的最多 24 条已有记忆进行冲突检查。检测到矛盾时，新内容进入“需要裁决的冲突”，不会成为有效长期记忆；可选择替换旧内容、丢弃新候选或同时保留。替换会使依赖旧记忆的回答失效，原始来源保留。模型可能漏检或误报，检查失败会记入日志并保留新增内容，不自行覆盖旧记忆。

普通陈述先保存在历史；默认关闭自动提取时不会自动成为长期记忆，启用后按下述三档策略处理。旁听内容和助手回答不会自动提取为用户事实。

点击“新会话”创建新的当前对话，旧原文和记忆仍保留；重启同一运行数据目录中的应用也会恢复它们。可以在新会话继续问“我希望你如何回答？”或用原来事实中的关键词提问。

## 5. 查看原文与理解压缩

“长期记忆”页面展示候选、显式／结构化记忆、实体关系、摘要与会话原文。来源按钮打开记录详情，可逐层返回上游原文；“浏览更早的会话原文”可按会话分页读取。删除后的来源显示不可用。

持续监听或多轮聊天积累足够消息后，后台会对较早片段生成摘要，并保留原始记录。正常回答优先于后台压缩；新请求、会话切换或删除会使旧任务停止或失效。

运行日志中的 compression_start 和 compression_done 表示压缩开始／完成。后台优先处理旧会话积压，摘要足够时合并成第二、第三层；重启后续作。未出现摘要可能是尚未达到阈值、预算不足、前台忙或服务失败。页面能查看索引进度、退避状态，并手动重试。

设置中可启用语义检索，选择云端嵌入或已安装的 Ollama 模型。后台建立索引，回答前默认最多等待 1.5 秒，超时回退关键词；本机 bge-m3 查询可能超过此上限，可自行调整等待时间。涉及人名、日期和数字仍应回查原文。更换模型或地址会使用独立索引；“重建”只清理派生向量。

语言模型的上下文编码可自动识别部分 GPT 模型，或手动选择。点击“准备所选编码”才会下载并校验编码文件；未知或未准备的模型使用保守字节估算。通用编码不保证所有模型精确计数。

### v0.6 自动提取、候选与实体

在设置页开启“自动提取记忆”并保存，再选择生效策略。默认开关关闭、策略为“大部分确认”。启用后，后台使用当前聊天模型及其凭据处理用户文字与麦克风原文；云端模型会收到这些原文，并可能产生调用费用。不会自动提取助手回复、工具结果或桌面旁听。当前会话也可以在记忆页手动触发提取，仍需先启用开关。

| 策略 | 提取后的行为 |
| --- | --- |
| 自动生效 | 通过校验且没有检测到结构冲突的条目直接生效 |
| 仅必要时确认 | 结构冲突、模型标记的不确定／敏感／实体含糊条目进入候选 |
| 大部分确认 | 普通对话提取全部进入候选，等待接受或拒绝 |

三档都保留已检测冲突的裁决；修改策略不会批准已有候选。明确“记住”和手动添加保留原流程。模型可能漏标不确定性，原文摘录存在也不保证提取结论正确，建议初次使用保持默认档位。

“待确认候选”可接受、拒绝、查看证据或进入冲突处理。只有生效记忆进入长期记忆检索；“实体与关系”显示人物、项目、组织及其事实／关系，点击可查看原文、修正或删除。相同名称与类型会归组，不支持别名或同名人物自动消歧；冲突检查按相同实体与属性的不同值进行，不保证识别自然语言改写或旧纯文本记忆的所有矛盾。

拒绝／删除后，应用持久阻止该旧来源版本再次自动提取任何新事实；其他已经生效的记忆不因此删除。新原文或明确手动添加仍可创建记忆。保留的原文和其他摘要仍可能被检索；要移除原始信息，使用下面的来源删除功能。

后台按有限批次处理，前台对话优先。状态显示待处理来源、候选、失败和重试信息；过长且无法装入当前模型上下文的原文保留待处理并延后，不截断成事实，也不伪装为已完成。调整模型上下文预算后可以重试。模型需要支持结构化工具输出；不支持时不会偷偷切换模型。

确定性模型／输出错误会暂停；暂时性错误最多自动尝试三次（含首次），然后显示“已暂停”。检查配置后点击“提取当前会话”或后台重试恢复。暂停只保存安全错误码与设置版本，同配置下重启不会自动恢复提取。手动重试仍会实际调用所选服务。

## 6. 修正、删除和清空

在“长期记忆”页面：

- 对记忆点击“修正”，修改偏好或事实；新版本取代旧记忆。
- 对会话原文点击“修正”，纠正识别错误；旧原文及依赖它的摘要、记忆和回答会同步失效。
- 删除一条记忆只移除记忆及派生内容，原文来源仍保留。
- 删除原文会同时处理它的检索索引、派生摘要／记忆／回答与对应录音。
- “清空历史与关联记忆”移除全部原文及历史派生内容；保留你在记忆页面独立添加的无来源记忆，需要时再逐条删除。

因此，“忘记这个偏好”不等于所有相关原文自动消失。需要该信息不再从历史检索到时，应删除对应原文；外部 Skill 或全局指令中的同样内容需要到各自位置修改。

删除前会停止相关生成和识别，避免旧任务稍后写回。界面的删除和清空需要确认；这些操作不可撤销。应用外另存的文件、系统备份和云端服务记录不在本地删除范围内。

## 7. 导入现成 Skills

进入“技能库”，选择一个包含 SKILL.md 的文件夹，或包含多个技能的目录，点击导入。随后可独立启用、停用或移除注册。

- 原目录不被修改或复制；移动、删除原文件会使注册技能不可用，重新选择实际路径即可。
- 兼容带 YAML frontmatter 的 SKILL.md，也支持普通 Markdown。
- 选择依赖名称、描述和当前请求的关键词。可以明确提到技能名称帮助匹配。
- 引用只读取技能目录内、相关且大小受限的文本资料；越出技能目录的引用与逃逸链接会被拒绝，脚本和远程资源不在引用加载范围内。
- Skill 的工具／脚本依赖会显示限制。首版不会执行它附带的脚本、shell 命令或 MCP 调用。
- 运行日志中的 context 事件记录本次实际使用的 Skill、资源版本和截断状态。启用不代表每轮都会加载。

修改原 Skill 后，其版本会根据内容更新。大文件和复杂的工具型技能可能不适合首版；可以先使用短小、清晰的角色或工作方法技能验证效果。

## 8. 查看运行日志与排查

打开“运行日志”，按事件类型或 trace ID 筛选。回答中的追踪入口可帮助找到同一次交互的输入、决策、上下文、模型调用与阶段指标。

“请求审计快照”记录回复、旁听判断、记忆冲突及压缩的实际语言模型输入。默认只存元数据、来源 ID、配置/请求哈希和 Skill 版本。启用“保存完整请求快照”后，新请求保留当时的配置和实际注入 Skill 正文（单条上限 256 KB），外部 Skill 后续修改不会改写历史快照。应用凭据不归档。

打开快照时先显示元数据，可进一步查看正文或导出 JSON。正文导出会另行确认；副本可能包含私人对话，应用中的删除不会擦除已经另存的文件。来源被删除或修正时，应用内相应正文快照失效。快照按日志保留期清理；重启时未完成请求标为 interrupted_restart，不自动重放模型调用。

- 没有听到内容：先检查是否开始聆听、设备／程序是否选对，以及相应来源是否有声音。
- 有转写但没回答：检查预设、允许主动回应开关、提问触发规则、冷却或忙时延后事件。
- 有文字但无语音：检查语音开关和 TTS 错误；文字输出不会因此丢弃。
- 出现上下文预算错误：缩短当前输入／全局 Prompt，或按模型真实支持的容量调整上下文配置。
- 本地识别模型缺失：使用准备模型入口，不要假定开始监听会下载模型。
- 服务不可用：分别测试 ASR、LLM 和 TTS；不要只凭语言模型连通判断整条链路正常。

性能目标还没有完整验收。记录具体来源、预设、症状和 trace ID 有助于排查；提交公开问题时不要附上 API 密钥、connection.json 或未处理的私人转写。

## 9. 资料库、任务与产物（v0.3 开发版）

### 导入资料

在“资料库”页面填写 `.md` 文件或文件夹的完整路径，然后点击导入。桌面版也可以用“选择文件”“选择文件夹”按钮。目前只支持 Markdown；单个文件不超过 2 MB，每次最多 500 个；隐藏目录和符号链接会被跳过。

资料按标题和段落分块，详情里能看到每个片段的标题和行号。原文件修改后，点击“重新扫描”生成新版本，旧版本的引用随之失效。原文件被移走时，资料保留上次导入的内容，并标为“原文件已移走”。移除资料会删除它的片段和索引，以及引用它的回答。

对话时会自动检索相关资料，把它们作为参考数据。资料里写的“请执行……”之类的内容不会被当成你的指令。

### 生成纪要、待办和文档

有两种方式：

- 在“任务与产物”页面点击新建任务，填写标题，选择是否使用当前会话原文、使用哪些资料，还可以补充要求，并选择是否同时生成文档草稿。
- 直接在对话里说“帮我整理刚才会议的纪要”。模型会创建同样的任务。

任务在后台运行，不影响你继续对话。控制台显示每一步的状态、耗时和模型调用次数；模型服务临时出错时会自动重试，并在步骤旁显示。桌宠气泡只显示简化进度，例如“正在整理纪要 · 2/4”。进行中的任务可以取消，失败、取消或中断的任务可以从未完成的那一步继续。

完成后会生成三类产物：

- **纪要**：摘要、要点、决定、待办和未决问题。每条后面的 `[S1]` 等标记对应来源列表。没有来源的条目标“（未标注来源）”；原文没有明确说出负责人或期限时，写“未确认”。
- **待办**：可以逐条修改内容、负责人、期限和完成状态。它是清单，不会变成定时提醒。
- **文档草稿**：模型写的草稿。引用了不存在的来源时，会显示成 `[来源?]`。

打开产物可以切换版本、直接修改后保存为新版本，也可以写下修改意见，点击“按修改意见重新生成”。“导出 .md”会下载一份带“来源”一节的 Markdown 副本。资料或原文被删除或修改后，产物标为“来源已变更”，对应引用失效，但正文保留，由你决定重新生成、修改或删除。

请核对姓名、数字和期限。本轮只用虚构会议评测过，真实会议的准确性还没有验证。

## 10. 工具与授权（v0.3 开发版）

当你用文字或麦克风提出请求时，模型可以调用工具，例如“把结论保存到 notes/结论.md”或“打开这个网址”。旁听内容、导入资料、Skill 和工具返回的结果都不能发起或批准操作。

| 类别 | 工具 | 默认 |
| --- | --- | --- |
| 应用内 | 创建纪要任务 | 直接执行 |
| 只读 | 检索资料、列出文件、读取文件 | 直接执行 |
| 写入 | 写入文件、把产物导出到工作目录 | 每次询问，可以撤销 |
| 打开 | 打开工作目录中的文件或 http/https 网址、启动设置中登记的程序 | 每次询问，无法撤销 |
| 删除 | 把文件移入回收区 | 每次询问，可以撤销 |
| 命令 | 从工作目录启动 PowerShell 执行命令，60 秒超时 | 默认关闭；开启后每次询问，无法撤销 |

文件工具只能访问工作目录。命令工具不同：工作目录只是它的起始位置，命令本身可以访问整台电脑，因此只在理解命令含义时批准。默认的工作目录是运行数据下的 `workspace/`，可以在设置中追加目录，“打开工作目录”按钮可以直接打开它。写入只允许 `.md` 和 `.txt`。

**确认操作**。需要确认时，控制台顶栏会出现待确认数量，任务页显示操作内容、目标和原因，桌宠也会提示。确认时可以选择：

- **仅本次**：只批准这一次调用。
- **本任务内允许**：同一任务中再调用这个工具时不再询问。只适用于写入和打开类，不会写入设置。

删除和命令类每次都要单独确认。

**撤销**。写入会先备份被覆盖的文件，删除只移到回收区，所以这两类可以在操作记录中撤销。如果文件在操作之后又被改动，撤销会拒绝执行，以免覆盖你的修改。打开和命令无法撤销。

**语音确认**。默认关闭。在设置中开启时会先弹出警告，取消警告后开关保持关闭。开启后：

- 只接受麦克风里完整的一句“确认执行”或“取消执行”，也可以是“同意执行”“拒绝执行”等同类说法，前面可以加“大贤者”或“请”。
- 只适用于写入和打开类操作。
- 只在恰好一项操作等待确认、且没有正在播报时生效。
- 只确认你开口时已经存在的操作；等待识别或被延后的旧语音不能批准后来出现的操作。
- 语音确认只批准这一次。

**规则**。在“设置 → 工具与授权”可以为工具添加“允许／询问／拒绝”规则，用通配符匹配路径、网址或命令。拒绝优先于询问，询问优先于允许。删除和命令类不能设为始终允许，`*` 也不能设为允许。设置中也可以关闭全部工具。

每次调用都记录工具、参数、效果、发起来源、审批方式和结果，可以在任务详情和运行日志中查看。应用在工具执行期间关闭时，这次调用标为“结果未知”，重启后不会自动重试，请自行检查结果。

### 接入 MCP 外部工具

在设置页的“外部工具 · MCP”中填写服务 ID、Streamable HTTP 地址（例如 `http://127.0.0.1:8000/mcp`），按需填写保存凭据的**环境变量名**，然后保存并点击“发现工具”。配置只保存地址和变量名；不会在启动时自动连接。重启或修改服务配置后需要重新发现。

当前支持最多 4 个服务，每个最多 32 个工具。每次调用都进入任务页的点击确认流程，不能设置为始终允许或用语音批准。服务宣称的“只读”属性不会降低权限要求。执行前重新核对工具定义；定义变化时需要重新发现并发起新请求。发出调用后断连会记录为“结果未知”，并停止该任务后续工具调用。

“停用已发现工具”清除本次发现结果并撤销待执行任务／授权，保留服务配置。当前只支持 Streamable HTTP 和环境变量 Bearer 凭据；stdio 启动、OAuth、资源／提示词浏览、服务器发起的采样与输入请求尚未接入。MCP 服务器本身需要你事先启动。

## 11. 运行监控

左侧“运行监控”可查看当前状态与模型、最近 30 个任务的节点／继续位置、最近 20 次模型请求、长期记忆和摘要数量，以及实体数量、提取状态和候选数量。页面随运行事件刷新，也可以手动刷新；简单问答走流式短路径，不会单独创建任务图。

每次请求列出发给模型的消息顺序、角色、序列化字节数和内容指纹，以及原文／摘要／记忆／资料来源数量。上下文数值是本地 tokenizer 或 UTF-8 上界估算，包含工具和结构化输出定义；它不是供应商的精确计费用量。迁移前的请求可能缺少这些字段。

这里始终只展示消息元数据。点击“请求证据”进入审计记录；只有请求发生前已开启正文归档，且来源仍有效，才能另行查看正文。点击记忆的“查看与管理”可以确认候选、浏览实体和原文证据、修正、删除或处理冲突。多个 Agent 协同和远端追踪属于后续阶段。
