# GreatSage 使用说明

适用于 v0.2 alpha。先按 [README](../README.md) 启动应用；首次默认不监听、不播报、不保存录音，语义索引和全文请求归档也默认关闭。

## 1. 配置与开始聆听

在“设置”中分别配置语音识别、语言模型和语音合成。三者可以使用不同服务：例如 API 识别与语言模型搭配本地系统语音，或本地识别搭配云端语言模型。

保存后分别测试连接。测试通过只说明该配置在测试样本上返回了结果；它不等于所有语言、音源或低延迟目标都已通过验收。选择本地识别时，先安装可选依赖并使用准备模型入口；实际开始监听不应自动下载权重。

API 密钥可从环境变量读取，也可输入到设置中加密保存。密码框留空会保留之前保存的密钥。单独清除本地密钥后仍可能使用其环境变量；需要完全取消时同时清空该组件的环境变量名。

在“对话与感知”选择：

- 是否启用麦克风，以及使用哪个设备。
- 桌面音源：不监听、系统整体或一个指定程序。
- 需要指定程序时，先刷新程序列表再选择；程序重启后 PID 可能改变。

点击“开始聆听”后观察来源转写和运行状态。桌面声音与麦克风分别标记；同一句话的临时识别可能修订，稳定结果才进入会话原文。暂停聆听停止采集，重新启动不会恢复旧队列中的音频。

## 2. 选择秘书行为

| 预设 | 默认行为 | 例子 |
| --- | --- | --- |
| 对话伙伴 | 麦克风说完后回答；桌面内容作为背景 | 直接对麦克风提问 |
| 旁听助手 | 收集内容；在麦克风明确提问、叫名或发出请求时回答 | “大贤者，刚才讲了什么？” |
| 主动秘书 | 开启允许主动回应后，结合全局指令判断是否插话 | 关注正在讨论的风险，必要时简短解释 |

手动输入文字始终视为直接请求。旁听对明确叫名和请求使用快速路径；含糊提问和转述交给当前语言模型，最多等待 3 秒，失败时保持安静并记录原因。设置中可以关闭“旁听语义判断”并使用规则结果。该模型需要支持结构化输出；慢速本地模型可能超时，需要明确叫名或关闭语义判断。

全局指令可描述角色、关注点、表达方式和主动回应条件。例如：

> 回答尽量简短。旁听时关注讨论中的方案、结论和未决事项。只有信息确实有帮助时才插话，不需要回应每句背景对话。没有可靠依据时说明不确定。

明确设置优先于这段指令：关闭允许主动回应时，不会仅因 Prompt 提到“主动提醒”就绕过开关。首版不会设置闹钟，也不会执行电脑操作。

## 3. 文字、语音和桌宠

设置输出语言和是否播报。文字与语音语言不同时，语音文本可能额外调用语言模型翻译，会增加时延与调用量。

语音按片段生成并排队播放。你可以使用打断入口或在麦克风中开始说话；界面会取消未完成回复和待播语音。语音服务失败时保留文字，并在日志显示错误。已经显示的部分回答会保留，但不代表你已经听完。

控制台和桌宠跟随 Windows 的浅色／深色模式。在侧栏点击“显示桌宠”或“收起”控制桌宠窗口。显示桌宠后可拖动位置、进行摸摸互动并查看气泡与状态动画。主窗口关闭后可能收起到托盘；使用托盘退出才结束整个应用。若启用了桌宠鼠标穿透，可通过托盘恢复鼠标操作。

目前的自身声音抑制不是完整 AEC。麦克风不根据文字相似度丢弃用户复述，只使用保守声学判断；文字去重用于桌面音源。扬声器回流、噪声和重叠说话会影响识别；先使用耳机有助于更清楚地验证秘书行为。

## 4. 让信息跨会话保留

可以在聊天或麦克风中明确说：

- “记住：我喜欢简短回答。”
- “请记住我希望默认用中文解释。”
- “Remember that I prefer concise replies.”

这些指令会创建来源指向当前用户消息的长期记忆。也可以在“长期记忆”页面填写内容并点击“添加记忆”；手动添加的记忆没有历史来源。

新记忆会与相关的最多 24 条已有记忆进行冲突检查。检测到矛盾时，新内容进入“待确认的记忆”，不会成为有效长期记忆；可选择替换旧内容、丢弃新候选或同时保留。替换会使依赖旧记忆的回答失效，原始来源保留。模型可能漏检或误报，检查失败会记入日志并保留新增内容，不自行覆盖旧记忆。

普通陈述仍保存在历史，但不会被自动认定为长期用户偏好。旁听内容和助手回答也不会自动成为用户事实。

点击“新会话”创建新的当前对话，旧原文和记忆仍保留；重启同一运行数据目录中的应用也会恢复它们。可以在新会话继续问“我希望你如何回答？”或用原来事实中的关键词提问。

## 5. 查看原文与理解压缩

“长期记忆”页面展示显式记忆、摘要与会话原文。来源按钮打开记录详情，可逐层返回上游原文；“浏览更早的会话原文”可按会话分页读取。删除后的来源显示不可用。

持续监听或多轮聊天积累足够消息后，后台会对较早片段生成摘要，并保留原始记录。正常回答优先于后台压缩；新请求、会话切换或删除会使旧任务停止或失效。

运行日志中的 compression_start 和 compression_done 表示压缩开始／完成。后台优先处理旧会话积压，摘要足够时合并成第二、第三层；重启后续作。未出现摘要可能是尚未达到阈值、预算不足、前台忙或服务失败。页面能查看索引进度、退避状态，并手动重试。

设置中可启用语义检索，选择云端嵌入或已安装的 Ollama 模型。后台建立索引，回答前默认最多等待 1.5 秒，超时回退关键词；本机 bge-m3 查询可能超过此上限，可自行调整等待时间。涉及人名、日期和数字仍应回查原文。更换模型或地址会使用独立索引；“重建”只清理派生向量。

语言模型的上下文编码可自动识别部分 GPT 模型，或手动选择。点击“准备所选编码”才会下载并校验编码文件；未知或未准备的模型使用保守字节估算。通用编码不保证所有模型精确计数。

## 6. 修正、删除和清空

在“长期记忆”页面：

- 对记忆点击“修正”，修改偏好或事实；新版本取代旧记忆。
- 对会话原文点击“修正”，纠正识别错误；旧原文及依赖它的摘要、记忆和回答会同步失效。
- 删除一条记忆只移除记忆及派生内容，原文来源仍保留。
- 删除原文会同时处理它的检索索引、派生摘要／记忆／回答与对应录音。
- “清空历史与关联记忆”移除全部原文及历史派生内容；保留你在记忆页面独立添加的无来源记忆，需要时再逐条删除。

因此，“忘记这个偏好”不等于所有相关原文自动消失。需要该信息不再从历史检索到时，应删除对应原文；外部 Skill 或全局指令中的同样内容需要到各自位置修改。

删除前会停止相关生成和识别，避免旧任务稍后写回。界面的删除和清空需要确认；这些操作不可撤销。应用外另存的文件、系统备份和云端服务记录不在本地删除范围内。

## 7. 导入现成 Skills

进入“技能库”，选择一个包含 SKILL.md 的文件夹，或包含多个技能的目录，点击导入。随后可独立启用、停用或移除注册。

- 原目录不被修改或复制；移动、删除原文件会使注册技能不可用，重新选择实际路径即可。
- 兼容带 YAML frontmatter 的 SKILL.md，也支持普通 Markdown。
- 选择依赖名称、描述和当前请求的关键词。可以明确提到技能名称帮助匹配。
- 引用只读取技能目录内、相关且大小受限的文本资料；越出技能目录的引用与逃逸链接会被拒绝，脚本和远程资源不在引用加载范围内。
- Skill 的工具／脚本依赖会显示限制。首版不会执行它附带的脚本、shell 命令或 MCP 调用。
- 运行日志中的 context 事件记录本次实际使用的 Skill、资源版本和截断状态。启用不代表每轮都会加载。

修改原 Skill 后，其版本会根据内容更新。大文件和复杂的工具型技能可能不适合首版；可以先使用短小、清晰的角色或工作方法技能验证效果。

## 8. 查看运行日志与排查

打开“运行日志”，按事件类型或 trace ID 筛选。回答中的追踪入口可帮助找到同一次交互的输入、决策、上下文、模型调用与阶段指标。

“请求审计快照”记录回复、旁听判断、记忆冲突及压缩的实际语言模型输入。默认只存元数据、来源 ID、配置/请求哈希和 Skill 版本。启用“保存完整请求快照”后，新请求保留当时的配置和实际注入 Skill 正文（单条上限 256 KB），外部 Skill 后续修改不会改写历史快照。应用凭据不归档。

打开快照时先显示元数据，可进一步查看正文或导出 JSON。正文导出会另行确认；副本可能包含私人对话，应用中的删除不会擦除已经另存的文件。来源被删除或修正时，应用内相应正文快照失效。快照按日志保留期清理；重启时未完成请求标为 interrupted_restart，不自动重放模型调用。

- 没有听到内容：先检查是否开始聆听、设备／程序是否选对，以及相应来源是否有声音。
- 有转写但没回答：检查预设、允许主动回应开关、提问触发规则、冷却或忙时延后事件。
- 有文字但无语音：检查语音开关和 TTS 错误；文字输出不会因此丢弃。
- 出现上下文预算错误：缩短当前输入／全局 Prompt，或按模型真实支持的容量调整上下文配置。
- 本地识别模型缺失：使用准备模型入口，不要假定开始监听会下载模型。
- 服务不可用：分别测试 ASR、LLM 和 TTS；不要只凭语言模型连通判断整条链路正常。

性能目标还没有完整验收。记录具体来源、预设、症状和 trace ID 有助于排查；提交公开问题时不要附上 API 密钥、connection.json 或未处理的私人转写。
