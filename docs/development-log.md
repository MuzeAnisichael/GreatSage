## 2026-10-17 · 框架审批与取消边界

- 审批改用 LangGraph interrupt / resume，等待时释放任务位置，不再挂起一个 Future。每个工具单独确认，批准值绑定调用 ID 和本地审批记录。
- 取消已批准但还在排队的任务，也会撤销未执行授权；取消／重启后恢复需要重新确认。修复来源删除期间任务仍持有上下文的问题：先取消任务并撤销审批，再清除中间内容。
- 全量 **219 passed、5 skipped**（23.80 秒），新增逐工具中断、等待时释放执行位置、已批准但尚未执行时取消、来源删除后旧审批失效等测试。
- 真实模型冒烟（单次简单问答，不是性能基准）：OpenRouter `google/gemini-2.5-flash-lite` 首字 1,416 ms、总计 1,481 ms，正确回答，费用 $0.0000039；Ollama `gemma3:4b` 首字 13,984 ms、总计 14,077 ms，正确回答。`qwen3:4b` 首字 27,900 ms，生成到 64 token 仍是冗长分析，只能确认连通，未通过回答质量检查。没有把冷／热启动状态未控制的单次样本宣传为稳定延迟。

## 2026-10-17 · MCP 工具接入首片

- 采用官方 MCP SDK 2.3 的 Streamable HTTP 客户端；设置页可保存服务、显式发现和停用工具，凭据只引用环境变量。会话按操作创建并关闭，没有隐式启动程序或连接。
- 外部工具仍通过 `tools.py` 权限层：逐次点击、禁止持续授权／语音批准、不信任服务的只读声明。用 JSON Schema 校验参数，禁止外部 schema 引用；执行前重新检查完整工具描述与服务配置版本。
- 远端调用发出后断连记为结果未知，不自动重试，任务也不再向模型提供后续工具。配置变化／停用使迟到的发现结果失效。
- 验证：全量 **227 passed、5 skipped**（30.96 秒），前端语法检查通过。包含官方 SDK 的模拟 HTTP 协议、定义变化、断连、授权隔离、迟到结果，以及完整 Agent → 点击确认 → MCP 调用回归。尚未对第三方实际 MCP 服务做互操作验收；stdio、OAuth、资源和服务端采样留待后续切片。
