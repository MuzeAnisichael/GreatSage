# v0.4：通用框架迁移

2026-10-16 用户确认开始渐进迁移，要求按模块小切片提交，并持续维护开发日志。本文是实施范围；已完成情况见[开发日志](development-log.md)，不代表已经发布。

## 目标与边界

保留 Windows 桌面、桌宠、文字／语音交互和已有数据，用通用开源组件替换通用 Agent 基础设施。API 优先，同时保留 Ollama。本轮优先迁移模型、任务编排和工具接入，并补充本地运行监控；不同时重写音频、记忆与 UI。

| 模块 | 采用方案 | GreatSage 保留的职责 |
| --- | --- | --- |
| 模型 | LangChain 的 OpenAI 兼容和 Ollama 适配器 | 配置、凭据、代理、超时、错误脱敏、流式事件兼容、审计 |
| 编排 | LangGraph 状态图与本地 SQLite checkpoint | 来源与版本校验、任务／会话隔离、工具执行账本、取消与未知结果处理 |
| 工具 | MCP SDK 接入标准工具 | 统一权限层、默认逐次审批、效果分级、执行审计；远端工具不能自授权限 |
| 监控 | 本地运行状态与上下文检查界面 | 默认元数据、显式正文归档；以后接入 OpenTelemetry／本地 MLflow |

简单问答保留流式短路径，多步骤任务进入图编排。Skill 仍只读。记忆和资料继续使用现有来源／版本／删除传播规则。checkpoint 只存引用和控制状态，避免另存一份无法随来源删除的对话内容。审批与副作用执行账本不能被框架默认行为绕过；重启后不自动重放结果未知的操作。

## 提交顺序与验收

1. 记录现状、基线、范围和后续顺序。
2. 迁移模型适配：API／Ollama、流式文本与工具参数、结构化输出、取消和安全错误回归。
3. 迁移任务图：纪要步骤与工具循环，持久化控制状态；取消、恢复、过期审批和工具不重放回归。
4. MCP 接入：显式配置、受控连接／发现／执行、审批与断连处理；外部输出只作为数据。
5. 运行监控：任务节点、状态、消息／上下文元数据与现有来源／审计入口；重连和不泄露正文回归。

每片更新日志，记录实际验证结果后独立 commit；阶段推送到 GitHub。原有数据库与配置保持兼容；依赖版本写入项目清单。默认不进行真实麦克风采集，不执行用户文件写入或命令作为测试，使用临时目录与虚构数据。
