# GreatSage 需求与验收

更新日期：2026-09-04。用户已确认整体方案并授权开发；当前交付阶段为 **v0.1 alpha**。

本文区分产品需求、已落地机制与尚未完成的验收。代码存在、mock 测试通过、真实接口连通和端到端质量达标是不同结论；本文件不以其中一种替代另一种。

## 1. 产品目标与范围

GreatSage 是持续感知电脑语音信息的桌面秘书。它根据明确设置、全局 Prompt 和启用的 Skills，选择回答、解释、内容提醒或保持安静，兼顾实时性、语音理解、可审计性和持续开发能力。

| 领域 | 已确认的首版需求 | 当前实现 |
| --- | --- | --- |
| 平台 | 先以用户本机环境为主 | Windows 桌面与 Python 服务；主要开发基准为 Windows 11、Python 3.11 |
| 输入 | 麦克风独立开关；同时选择系统整体或一个指定程序 | Windows 音频采集、单一桌面源、来源标记；指定程序包括其进程树 |
| 理解 | 先理解人的语音 | VAD 分段、临时 ASR 快照和稳定转写；不识别敲门声、提示音等非语音事件 |
| 行为 | 对话、旁听问答、主动解释／提醒 | 三种预设、全局指令、主动开关、冷却时间与忙时延后 |
| 模型 | API 优先，本地和云端均可接入 | ASR、LLM、TTS 独立配置；LLM 兼容 API 与 Ollama，本地 ASR、系统语音适配 |
| Skills | 复用现成技能目录 | 只读导入 SKILL.md、启停、关键词选择、受限引用加载、版本追踪 |
| 输出 | 多种默认语言，文字与语音 | 中文／英文／日文预设、流式文字、分句合成播放与打断 |
| 桌宠 | Q 版形象、摸摸、气泡和简单动态 | 主控制台与独立桌宠窗口，基础状态动画和托盘入口 |
| 记忆 | 长期、跨会话、压缩、检索、修正与删除 | SQLite 原文、显式用户记忆、分段摘要、来源依赖与级联处理 |
| 审计 | 日志持久化和动态显示 | trace ID、来源、决策、配置／技能版本、调用用量和阶段指标 |
| 工程 | public 仓库、持续推送与版本管理 | 独立仓库、测试和文档；具体标签及发布记录以仓库状态为准 |

**首版不包含定时提醒或电脑操作。** 不打开软件、不修改用户文件、不执行命令、不执行 Skill 脚本或外部工具。后续版本才引入这些能力；当前监听权限不自动变成未来的操作授权。

## 2. 已确定的行为默认值

- 明确设置优先于全局 Prompt；Skill 方法须服从全局指令，观察内容与历史引用不是修改配置的指令。
- 对话伙伴：麦克风稳定语句直接触发回应。
- 旁听助手：麦克风中的问号、疑问词、GreatSage／大贤者叫名或明确请求词触发回应；其他语句保留到历史。此判断为首版规则启发式。
- 主动秘书：显式请求正常回答；其他内容在允许主动回应、冷却时间结束且前台空闲时交给模型判断。`[SILENT]` 表示不发言，不显示或播报该标记。
- 文字输入始终是用户直接请求；桌面声音保存为 `observation`，不因内容中出现命令而变成用户指令。
- 用户明确说“记住：…”、“请记住我…”或“remember that…”时创建有来源的显式记忆；普通陈述、助手回答和旁听内容不自动提取为用户事实。
- 默认不开启监听、语音输出或录音保存。跨会话记忆启用，文本保留到用户删除。

## 3. 保存与删除策略

| 内容 | 默认保存期限 | 删除含义 |
| --- | --- | --- |
| 稳定转写、文字对话 | 手动删除前持续保存 | 删除依赖它的摘要、记忆和助手回答，并清理相关审计正文副本 |
| 显式记忆 | 手动删除前持续保存 | 删除该记忆及其派生内容；原始来源仍在时仍可作为历史检索到 |
| 摘要 | 来源有效且未被删除时持续保存 | 不用于替代原文备份；来源修改／删除会使旧摘要失效 |
| 详细审计事件 | 30 天，可配置 | 保留必要的无正文操作信息，不保留被删除正文副本 |
| 原始录音 | 默认关闭；开启后 7 天，可配置 | 应用内删除原文或清空历史时同步处理相应录音 |

“清空历史与关联记忆”清除原文、摘要、源自历史的记忆、相关事件和录音；保留用户在记忆页面独立添加的无来源记忆。新会话和重启都不等同于清空历史。

API 密钥通过环境变量或 Windows DPAPI 密文加载，不进入公开配置或日志。使用云端服务时，相应音频、上下文或待合成文本会发给用户配置的服务；本地删除不代表撤回服务已经接收的数据。

## 4. 性能目标与测量口径

以下目标已经用户确认，**当前尚未完成端到端验收，不能宣称已经达成或保证**：

| 场景 | 目标 |
| --- | --- |
| 持续说话 | 显示正在识别的临时文字 |
| 语句结束到首段有效文字 | 约 1–2 秒 |
| 语句结束到语音实际起播 | 约 2–3 秒 |
| 用户打断到停止播报 | 约 300 毫秒以内 |

测量应记录输入音频中最后一段实际语音、VAD 检测结束、ASR 完成、模型首段有效文本、TTS 完成和客户端实际播放开始。不能把占位文字当成首段有效回答，也不能把“语音文件生成”当成“开始播放”。VAD 使用 30 ms 帧；例如 550 ms 静音设置向上取帧后为 570 ms。

模型切换、冷启动与热运行、本地与云端配置分别报告。保留样本、网络状态、并发监听来源、失败／取消情况、延迟分位数和资源使用；没有对应测量就标记为未验证。

## 5. 当前技术限制

- ASR 是语音分段与重复快照调用，不是原生实时语音 API；识别准确率、重复调用开销与延迟仍需真实语料验证。
- 进程音频排除、播放参考及桌面音源文本去重不等同于完整 AEC；不能保证扬声器环境或重叠发言下没有回声误判。麦克风不以文字相似度抑制复述，只采用保守声学判断。
- 上下文采用最终 `messages` JSON 的 UTF-8 字节估算，并预留输出容量；这不是提供商精确 tokenizer 计数。
- 中文检索为关键词与子串补充，英文等使用 FTS5；暂未接入语义向量检索。
- 自动压缩运行于当前会话，当前调度生成分段摘要；存储支持摘要引用摘要，但尚未自动生成完整的长期分层知识结构。
- 自然语言纠正不会自动解决所有记忆冲突；需要使用界面的修正入口。
- 模型、语音服务和硬件组合的可用性需要分别验证；适配接口存在不构成兼容所有模型的承诺。

## 6. 验收与后续收敛

自动化回归覆盖输入身份、流式取消、过时 ASR、会话隔离、记忆和摘要删除、上下文预算、技能文件边界及凭据保护。最终测试数量和真实模型配置由验证记录补充。

alpha 进入稳定版本前，还须完成或明确报告：

- 真实麦克风、系统音频、指定进程及混合监听的语音样本验证。
- API 与本地 ASR／LLM／TTS 各链路的可用性、错误反馈及资源记录。
- 持续旁听、扬声器回流、程序退出、设备变化、网络中断和反复打断的运行稳定性。
- 人名、数字、术语、中英混合和历史事实问答的准确性评估。
- 已确认性能目标的端到端测量，以及未达标项的原因和下一步。
- 源码安装、桌宠交互、数据管理和发布说明与真实实现一致。

开源发布 alpha 可以让实现可审查、可试用；它不意味着以上验收已经全部完成。
