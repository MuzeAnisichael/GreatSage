# GreatSage 需求与验收

2026-11-18 更新。v0.9 将 v0.8 的会话、证据和文档修订用于跨天接续工作。用户确认了单会话简报、文字与可编辑语音纠正、写文件时独立审批三项范围。各版本的证据与未测边界见[项目现状](project-status.md)和[v0.9 验证](validation-v0.9.md)。

本文区分产品需求、已落地机制与尚未完成的验收。代码存在、mock 测试通过、真实接口连通和端到端质量达标是不同结论；本文件不以其中一种替代另一种。

## 1. 产品目标与范围

GreatSage 从持续感知电脑语音信息的桌面秘书起步。它根据明确设置、全局 Prompt 和启用的 Skills，选择回答、解释、内容提醒或保持安静，兼顾实时性、语音理解与可审计性。后续目标是在文字／语音、资料检索和受控工具之间完成可审阅的任务产物。

| 领域 | 已确认的首版需求 | 当前实现 |
| --- | --- | --- |
| 平台 | 先以用户本机环境为主 | Windows 桌面与 Python 服务；主要开发基准为 Windows 11、Python 3.11 |
| 输入 | 麦克风独立开关；同时选择系统整体或一个指定程序 | Windows 音频采集、单一桌面源、来源标记；指定程序包括其进程树 |
| 理解 | 先理解人的语音 | VAD 分段、临时 ASR 快照和稳定转写；不识别敲门声、提示音等非语音事件 |
| 行为 | 对话、旁听问答、主动解释／提醒 | 三种预设、全局指令、主动开关、冷却时间与忙时延后 |
| 模型 | API 优先，本地和云端均可接入 | ASR、LLM、TTS 独立配置；LLM 兼容 API 与 Ollama，本地 ASR、系统语音适配 |
| Skills | 复用现成技能目录 | 只读导入 SKILL.md、启停、关键词选择、受限引用加载、版本追踪 |
| 输出 | 多种默认语言，文字与语音 | 中文／英文／日文预设、流式文字、分句合成播放与打断 |
| 桌宠 | Q 版形象、摸摸、气泡和简单动态 | 主控制台与独立桌宠窗口，基础状态动画和托盘入口 |
| 记忆 | 长期、跨会话、压缩、检索、修正与删除 | SQLite 原文、显式／结构化记忆、候选与实体、三级摘要、词法／可选语义检索、来源依赖、冲突裁决与级联处理 |
| 会话工作台（v0.8） | 返回历史对话继续交流，定位关联工作 | 持久当前会话入口、显式激活旧会话、关联任务／产物筛选；重启不自动聆听、恢复任务或发起后台模型维护 |
| 审计 | 日志持久化和动态显示 | trace ID、来源、配置／实际 Skill 版本、请求快照、受控导出、阶段指标和服务返回的用量 |
| 资料（v0.3） | 导入资料并带出处引用 | `.md` 文件或目录；按标题和段落分块，记录行号和内容版本；重新扫描生成新版本，删除或修改后旧引用失效 |
| 产物（v0.3） | 纪要、待办和文档草稿 | 版本化 Markdown 与引用表；待办可编辑；支持纠正后重新生成和导出 `.md` |
| 研究（v0.7 底座） | 选定资料 → 证据核对 → 可审阅文档 → 批准保存 | 两个固定只读子角色顺序委派、严格来源／引文校验、分歧与待确认项、版本绑定逐次点击保存；历史真实模型结果见 v0.7 验证，不推定本轮通过 |
| 来源选择（v0.8） | 在明确所选范围内自动选材，必要时调整 | 固定 ID／哈希／资料版本，在范围内本地词法排序；支持固定／排除、完整范围与显式来源更新，失败不静默缩小全文范围 |
| 连续审阅修订（v0.8） | 对照原文、查看差异、纠正后产生可追溯新版本 | 引用定位和状态、文本差异、生成任务／父版本／纠正来源；expected_version 防旧编辑覆盖，版本与内容哈希绑定新保存 |
| 跨天接续（v0.9） | 隔天回到项目时，找回已定事项、后续行动和悬而未决的问题 | 在单一会话的本机日期范围及显式选取的 Markdown 中选择原文，生成三栏简报。文字或可编辑语音转写经用户提交才修订，文件写入单独审批 |
| 工具（v0.3） | 受控执行有副作用的操作 | 效果分级、授权规则、点击审批、可选语音确认、工作目录沙箱、撤销与审计；命令工具默认关闭 |
| 框架（v0.4–v0.7） | 复用通用开源技术，渐进迁移并保留数据与权限语义 | LangChain 聊天、LangGraph 任务／审批、MCP HTTP、Pipecat 音频、LangMem 结构提取；v0.7 Deep Agents 固定资料整理／证据核对只读委派 |
| 监控（v0.4–v0.7） | 查看消息、上下文、记忆与运行状态 | 本地节点／checkpoint、消息目录、预算估算、记忆数量和变更、实体／候选及提取状态；v0.7 展示计划、固定子 Agent 状态及实际用量，尚无远端追踪 |
| 工程 | public 仓库、持续推送与版本管理 | 独立仓库、小切片提交、测试、版本标签、文档和 GitHub 预发布 ZIP／实验性安装器；人工安装验收尚待完成 |

**v0.1 和 v0.2 不包含定时提醒或电脑操作。** 它们不打开软件、不修改用户文件、不执行命令，也不执行 Skill 脚本或外部工具。v0.3 开始，工具调用必须经过 `greatsage/tools.py` 的权限层；监听权限不会自动变成操作授权。Skill 脚本仍不执行。

**v0.3 的产品目标**是连通文字／语音输入、资料检索、带出处的纪要／待办／文档产物和受控工具执行；支持进度显示、取消、任务切换与故障恢复，并完成 Windows 安装和长任务验收。2026-09-30 用户确认了以下细节：

- 首批资料格式是 `.md`，产物以 `.md` 为主。
- 工具授权参照主流前沿 agent 设计。
- 有副作用的操作默认需要点击确认；可以在设置中开启语音确认，但开启时必须弹出警告。
- 详细进度在控制台显示，桌宠气泡只显示简化版。

待办先指任务清单，不自动变成定时提醒。具体设计见 [v0.3 开发方案](v0.3-plan.md)，顺序见[路线图](roadmap.md)。

## 2. 已确定的行为默认值

- 明确设置优先于全局 Prompt；Skill 方法须服从全局指令，观察内容与历史引用不是修改配置的指令。
- 对话伙伴：麦克风稳定语句直接触发回应。
- 旁听助手：明确叫名/请求快速回应，含糊提问或转述默认进行限时语义判断，可设置关闭；识别不确定或服务失败时保持安静。明确请求安静优先，历史仍保留。
- 主动秘书：显式请求正常回答；其他内容在允许主动回应、冷却时间结束且前台空闲时交给模型判断。`[SILENT]` 表示不发言，不显示或播报该标记。
- 文字输入始终是用户直接请求；桌面声音保存为 `observation`，不因内容中出现命令而变成用户指令。
- 只有你的文字、麦克风请求和控制台操作可以发起工具调用。旁听内容、导入资料、Skill 和工具返回的结果都是参考数据，不能发起或批准操作。
- 读取类工具直接执行。写入、打开和删除每次询问，命令工具默认关闭。审批默认用鼠标点击；开启语音确认后只接受完整的确认短语，而且只适用于写入和打开类操作。
- MCP 外部工具不能沿用服务端声称的只读权限；一律逐次点击确认，不接受语音或本任务持续授权。工具目录显式发现，配置变化／停用／重启需要重新发现；定义变化必须重新发起请求。
- 用户明确说“记住：…”、“请记住我…”或“remember that…”时创建有来源的显式记忆；普通用户陈述仅在启用自动提取后按三档策略处理；助手回答和旁听内容不自动提取为用户事实。
- 默认不开启监听、语音输出或录音保存。跨会话记忆启用，文本保留到用户删除。
- 重启恢复最近持久会话入口；旧任务需显式继续，后台摘要／提取等维护需明确交互后才按原设置调度。激活旧会话与恢复旧任务分别操作。
- 研究默认在所选范围内自动选取相关完整片段并执行，不新增选材确认。完整范围或固定片段不能放入预算时可见失败；更新资料版本必须显式开启 `update_sources`。
- 研究修订的用户要求保存为独立用户消息；旧模型草稿仅作待修改上下文，不成为原始证据。每版保存重新点击批准，不能继承旧版本授权。

## 3. 保存与删除策略

| 内容 | 默认保存期限 | 删除含义 |
| --- | --- | --- |
| 稳定转写、文字对话 | 手动删除前持续保存 | 删除依赖它的摘要、记忆和助手回答，并清理相关审计正文副本 |
| 显式记忆 | 手动删除前持续保存 | 删除该记忆及其派生内容；原始来源仍在时仍可作为历史检索到 |
| 摘要 | 来源有效且未被删除时持续保存 | 不用于替代原文备份；来源修改／删除会使旧摘要失效 |
| 详细审计事件 | 30 天，可配置 | 保留必要的无正文操作信息，不保留被删除正文副本 |
| 原始录音 | 默认关闭；开启后 7 天，可配置 | 应用内删除原文或清空历史时同步处理相应录音 |
| 导入的资料（v0.3） | 移除前持续保存导入时的片段副本 | 移除资料会删除片段、索引和引用它的回答；产物保留正文，但标为“来源已变更” |
| 产物与版本（v0.3） | 手动删除前持续保存 | 只有删除产物才移除正文；来源变化只让对应引用失效 |
| 任务与工具调用记录（v0.3） | 手动删除前保存状态和审计信息 | 任务成功后清除中间正文；工具的备份和回收区文件用于撤销 |
| 图 checkpoint（v0.4） | 随任务保存 | 只含控制状态与引用；删除任务时清除，正文仍走原数据层删除规则 |
| 当前会话入口（v0.8） | 保存到用户切换或清空历史 | 单一会话 ID 指针，不含正文副本；清空历史后新建有效入口 |
| 研究范围与修订血缘（v0.8） | 随任务／产物保存 | 范围保存 ID／哈希／资料版本；血缘保存生成任务／父版本／纠正来源 ID。来源删除清理派生研究正文与引用摘录；产物正文仍按产物规则保留 |

“清空历史与关联记忆”清除原文、摘要、源自历史的记忆、相关事件和录音；保留用户在记忆页面独立添加的无来源记忆。新会话和重启都不等同于清空历史。清空历史不删除导入的资料和产物，但会有以下变化：

- 产物中指向会话原文的引用失效，产物标为“来源已变更”。
- 任务的中间正文被清除。
- 含正文的工具参数被清除。
- 当前会话入口重建；修订中指向纠正消息的来源关系失效。已下载／写入外部文件的副本不因应用内删除而自动撤回。

API 密钥通过环境变量或 Windows DPAPI 密文加载，不进入公开配置或日志。使用云端服务时，相应音频、上下文或待合成文本会发给用户配置的服务；本地删除不代表撤回服务已经接收的数据。

## 4. 性能目标与测量口径

以下目标已经用户确认，**当前尚未完成端到端验收，不能宣称已经达成或保证**：

| 场景 | 目标 |
| --- | --- |
| 持续说话 | 显示正在识别的临时文字 |
| 语句结束到首段有效文字 | 约 1–2 秒 |
| 语句结束到语音实际起播 | 约 2–3 秒 |
| 用户打断到停止播报 | 约 300 毫秒以内 |

测量应记录输入音频中最后一段实际语音、VAD 检测结束、ASR 完成、模型首段有效文本、TTS 完成和客户端实际播放开始。不能把占位文字当成首段有效回答，也不能把“语音文件生成”当成“开始播放”。VAD 使用 30 ms 帧；例如 550 ms 静音设置向上取帧后为 570 ms。

模型切换、冷启动与热运行、本地与云端配置分别报告。保留样本、网络状态、并发监听来源、失败／取消情况、延迟分位数和资源使用；没有对应测量就标记为未验证。

## 5. 当前技术限制

- 原有 ASR 使用语音分段与重复快照，v0.5 另提供可选 Deepgram 原生流式路径；两条路径的真实识别质量、开销与延迟需要分别验证。
- 进程音频排除、播放参考及桌面音源文本去重不等同于完整 AEC；不能保证扬声器环境或重叠发言下没有回声误判。麦克风不以文字相似度抑制复述，只采用保守声学判断。
- 对已经准备且适用的模型编码使用 tokenizer；未知模型回退保守的序列化 UTF-8 字节预算，并预留输出及协议容量。不将某个编码视为所有服务的精确计数。
- 历史与记忆已有词法／可选语义混合检索，按嵌入服务和模型版本隔离索引。查询超时或服务失败回退词法。v0.3 的资料库只支持 `.md`；PDF、Word 和网页等格式尚未支持。
- 明确交互启用本次运行的后台调度后，可按设置继续处理旧会话原文并形成三级摘要；原文保留且可回查。固定小型集的事实字面保留结果不证明复杂关系无误。
- v0.8 自动选材使用本地词法评分，没有新增语义检索／重排算法。引用可定位和逐字引文合法不证明结论受原文蕴含；审阅接口返回 `semantic_verification=False`。原文选择与多轮修订的真实质量尚需单独评估。
- 冲突建议由用户裁决，修正使用新 ID 与递增版本并让旧依赖失效；不提供任意自然语言纠正的自动裁决或完整历史版本回滚。
- 模型、语音服务和硬件组合的可用性需要分别验证；适配接口存在不构成兼容所有模型的承诺。
- 当前构建包含 Windows 目录 ZIP 与实验性 NSIS，安装／升级／卸载和跨机器兼容尚未验收。迁移后已有合成服务下的实际进程中断／重启检查，但没有长时间运行或真实工作负载崩溃验收。

## 6. 验收与后续收敛

自动化回归覆盖输入身份、流式取消、过时 ASR、会话隔离、记忆和摘要删除、上下文预算、技能文件边界及凭据保护。最终测试数量和真实模型配置由验证记录补充。

alpha 进入稳定版本前，还须完成或明确报告：

- 真实麦克风、系统音频、指定进程及混合监听的语音样本验证。
- API 与本地 ASR／LLM／TTS 各链路的可用性、错误反馈及资源记录。
- 持续旁听、扬声器回流、程序退出、设备变化、网络中断和反复打断的运行稳定性。
- 人名、数字、术语、中英混合和历史事实问答的准确性评估。
- 已确认性能目标的端到端测量，以及未达标项的原因和下一步。
- 源码安装、桌宠交互、数据管理和发布说明与真实实现一致。

开源发布 alpha 可以让实现可审查、可试用；它不意味着以上验收已经全部完成。

## 7. v0.3 任务级需求与验收方向

这些是 v0.3 的目标和验收口径，已实现机制随 v0.4 alpha 交付。“当前状态”一列区分已落地机制和仍待完成的部分；实现了不等于已通过真实场景验收。

| 用户任务 | 需要的行为 | 验收重点 | 当前状态 |
| --- | --- | --- | --- |
| 理解资料 | 从用户选定资料与已有会话检索可用段落，记录来源和内容版本 | 来源可定位；资料修正／删除后旧索引与引用失效；不可把媒体观察提升为用户指令 | `.md` 已实现，含自动化测试；其他格式未做 |
| 生成产物 | 从文字或语音请求生成纪要、待办及文档草稿，并允许审阅、纠正和导出 | 姓名、数字、负责人、期限、事实关联、遗漏与不确定项可检查；引用与修订来源一致 | 已实现；2 个虚构会议的真实模型评测全部正确，真实会议未测 |
| 执行工具 | 在明确的权限范围内打开软件、处理文件或调用命令／工具，并显示结果 | 参数、操作对象、用户授权来源、副作用和失败均可审计；旁听内容不能直接触发有副作用操作 | 权限层、审批、撤销和审计已实现；真实桌面的打开和命令未测；v0.4 MCP HTTP 与真实模型工具调用的覆盖见[验证记录](validation-v0.4.md) |
| 管理长任务 | 提供进度与流式反馈；支持取消、切换会话／任务和故障后继续 | 迟到结果不串会话；取消后的状态明确；重启不重复执行已完成的有副作用步骤 | 已实现，迁移后增加实际进程中断的合成测试；长时间运行和真实工作负载未验收 |
| 安装与长期运行 | 安装、升级和卸载 Windows 桌面应用，保持既有运行数据 | 在干净环境验证安装、迁移、回滚／故障处理与长时间运行，而不以目录包 smoke test 代替 | NSIS／正常关闭／数据保留配置和人工验收脚本已实现；实际安装、跨版本升级和长运行待验收 |

评测以纪要、待办和文档任务的完整输入到最终产物为单位，同时统计以下内容：

- 产物正确性和记忆有效性。
- 误触发和越权操作。
- 首段有效反馈和任务总耗时。
- 取消与恢复后的结果。
- 资源和 API 用量。

先固定样本与基线，再确定数值阈值；每项都公开样本范围和未测边界。首轮基线见 [v0.3 验证](validation-v0.3.md)。

## 8. v0.8 工作台需求与验收边界

2026-11-18 已确认默认在明确所选范围内自动运行，完整范围／来源／预算问题必须可见停止。本轮最小流程是“继续昨日会话 → 选材研究 → 原文审阅 → 纠正并对比版本 → 重新批准保存”。以下记录当前机制与验收口径，执行证据及发布状态由本轮记录单独给出。

| 用户任务 | 当前机制 | 必须核对的边界 |
| --- | --- | --- |
| 继续历史会话 | 持久入口、会话激活锁与历史重载 | 未知 ID 无副作用；旧回答／转写／工具结果不串入新会话；重启不自动恢复工作 |
| 在所选资料中找证据 | 冻结范围后词法选材，固定／排除与完整范围模式 | 不搜范围外；不加入冻结后新消息；完整范围、固定项、过期来源和预算失败停止；旧版无快照任务不冒充历史读取范围 |
| 审阅与修订文档 | 引用定位、明确受限的文本 diff、独立纠正消息、版本血缘 | 旧草稿不是 evidence；并发版本冲突拒绝；纠正删除参与来源传播；显示截断不隐藏 |
| 保存与恢复 | 任务生命周期身份与有界清理、版本／内容哈希批准 | 旧授权失效；中断任务显式继续；未退场的旧运行不重复启动；结果未知不重放；拒绝保存仍保留产物 |

冻结范围最多 1500 条来源，研究实际读取最多 8 段、共 64,000 字符、单段 32,000 字符，并受模型完整请求预算约束。修订草稿最多 12,000 字符，合并全局要求后的完整指令最多 16,000 字符，超限拒绝而不截断；来源候选、审阅段落和 diff 有单独显示上限并返回限制标记。这些是实现边界，不是质量或性能目标。

定向回归负责权限、来源、并发和恢复的确定性约束；真实长资料选材召回、修订事实正确性、自然语音、实际安装／升级与长期使用必须独立记录。v0.8 不加入 PDF／Word／网页导入、屏幕感知、通用递归／并发 Agent、实体消歧、跨平台、定时提醒或首配清单。

## 9. v0.9 跨天工作接续验收

| 场景 | 可观察的结果 |
| --- | --- |
| 隔天找回决定 | 返回旧会话，按上次进展或本机日历的指定日期生成简报。先见记录数与起止时间，日期无记录可调整。核对三栏中决定、候选日期和建议的分类，每条内容可追溯原文。 |
| 连续纠正 | 先文字纠正负责人，再主动录入带否定词的期限。停止后可编辑转写，提交后看本次新版本与父版本的差异。未涉及事项及引用保留。关闭、切换会话或版本后迟到回包应失效。 |
| 保存与恢复 | 每次写文件前审阅目标路径、版本及哈希。拒绝保存仍可找回简报。重启后从所属会话查看历史版本，继续修订，核对新文件和对应审批。 |
